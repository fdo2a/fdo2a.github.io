# scripts/ja — Japanese edition (`ja/`)

Translates published Korean posts into a Japanese copy with the same skeleton, served under `ja/`. Scope: dailies only — `posts/`, `news/`, `japan/daily/` (+ their list json). **Not** the weeklies (`weekly/`, `japan/posts/`; user decision 2026-11-17 — links to them go to the Korean page, list pages lose the weekly tab), `kr/`, `thesis/`, `china/`. Widening the scope touches `runner.SCOPE*`, `assemble.ARTICLE`/`OUT_OF_JA_DIRS`, `lists.LISTS`, `pipeline.LIST_SOURCES`, `publish.LIST_FILES` and `site._WEEKLY` together. This is **not** `scripts/japan/` (the Korean-language Japan-market pipeline) — different package, different owner of files.

## Module map

| Module | Does |
|---|---|
| `extract.py` | HTML → skeleton + translation units (innermost block with direct text; attributes; JSON-LD strings); `join` puts units back |
| `news.py` | News items whose source record title has kana: original title + outlet, no summary (`localize`); `data_files` = the news data a post depends on |
| `glossary.py` | Fixed strings / rules / names (`NAMES` = verified surname + title only). `VERSION` is part of every unit key |
| `gate.py` | Machine checks: per unit (`check_unit`: empty, placeholders, Hangul left, number multiset, Latin tokens, length, kana; order/sign are soft) and per document (`check_doc`: zero Hangul outside the language button, `lang="ja"`, one analytics marker) |
| `state.py` | Sidecar `ja/_tm/<path>.json`, ledger `ja/state.json`, `classify` (new · fresh · reassemble · retranslate) |
| `assemble.py` | Build the Japanese page (lang, typography, canonical/og/hreflang, relative URLs, language button), `with_notice`/`without_notice`. **`RENDERER`** — bump by hand when assembly output changes; the runner then reassembles with zero model calls |
| `translate.py` | `claude -p` (subscription) per batch; `LimitReached` / `ModelError` / `BillingRisk` |
| `review.py` | codex review (read-only sandbox); `ReviewFailed` ≠ "no findings". Re-reviews get the unit's `history`; `IDIOMS` (not mistranslations) go into the prompt verbatim — extend there. `adjudicate`: one A/B/both/neither call for units still blocked after the fix loop |
| `pipeline.py` | `build_page` — one post end to end, writes nothing. `Result.status` ready · held · pending; `detail["stop"]` = news_missing · gate · names · review_failed · blocking · missing_units · doc · limit · model · auth · budget · fixed · news_lang · news_malformed. `text_hash_of` (no model) |
| `lists.py` | `ja/{posts,news}.json`, `ja/japan/daily.json` — only ledger `published`/`notice` pages, titles from the sidecar only while `list_src` equals the current Korean value |
| `site.py` | `ja/index.html`, `ja/japan/index.html` from the Korean list pages (rerun `python3 -m scripts.ja.site` after editing those) |
| `chart.py` | Japanese yield-curve PNG from the **git history** input of the Korean PNG (`render_why` → `(path, why)`) |
| `runner.py` | One tick (`tick`), brakes, `summary`/`digest_lines` for the morning digest |
| `publish.py` | Commit `ja/**` only and push |
| `scripts/ja_local.py` | `run` · `status` · `retry <path>` · `retry --auth` · `build <path> --out DIR` |

## Invariants

- **Never touch a Korean file.** The runner writes only under `ja/`; `publish.push` checks the **index** (`git diff --cached`) and raises `OutsideJa` without committing if any staged path is outside `ja/`. The only Korean-side edits are human ones (the 「日本語」 button in `index.html`, `japan/index.html`; the `ja` exclusion in `scripts/review/queue.py`).
- **Never use `scripts/ci/push_with_retry.sh` here.** `publish.push` refuses (`GitError`, nothing staged) if HEAD has any commit origin/main lacks (origin/main being ahead is fine — that takes the reject path). On rejection fetch, then abandon if `publish.CODE_PATHS` moved (the edition code plus the shared code it loads — `test_code_paths_cover_shared_code_the_edition_loads` follows the imports), if any of the three Korean list json (`LIST_FILES`) changed at all (the Japanese lists are rebuilt whole, so another page's item goes stale), or if any page's source or dependency (`expect`, which also carries news-data candidates that did not exist as `""`) differs; otherwise rebase and retry (3 pushes). Abandoning is cheap: translations survive in `cache_dir` and the next tick rebuilds with zero model calls.
- Numbers: the multiset per unit must match (`gate.check_unit`); **zero Hangul** in the assembled page (`gate.check_doc`) and in list json (`lists.build` raises).
- **A review failure is not "no findings"** — it holds the page. Blocking kinds are `review.BLOCKING`; 好み is logged only.
- **No billing path.** claude children run with `ANTHROPIC_*`/`CLAUDE_CODE_USE_*` removed and asserted absent (`BillingRisk`), `--setting-sources ''`; codex children with `OPENAI_API_KEY`/`CODEX_API_KEY`/`AZURE_OPENAI_API_KEY`/`ANTHROPIC_*` removed. Never add an API-key fallback.
- **Usage is metered per child process**, not per page: `translate.ON_CALL` (set only by the runner's `_Meter.hooked()`) fires before each `claude`/`codex` child (raise `translate.CapReached` → the call is not made, page `pending` with stop `budget`/`review_cap`) and after it (tokens / one review call written at once). A new call site that spawns a model must call `translate.hook`.
- Fixed translations are reviewed too: the first occurrence of each fixed (ko, ja) pair **not yet in the sidecar's `fixed_ok`** joins the review scope (localized Japanese headlines excepted); a blocking finding holds the page (`fixed`), a pass adds the pair to `fixed_ok`. So a glossary value change + `RENDERER` bump costs one review call per live page (rate-limited by the caps); until it passes the served page stays as is.
- **What the machine gate guarantees vs. what it only flags.** Hard (`gate.check_unit`): number multiset; currency per number-attached unit incl. dollar kinds (`currency`); the scale char right after every number, 억·만·조… ↔ 億·万·兆…, as a multiset, and per-number order when one number carries different scales (`scale`); Latin tokens with boundaries; zero Hangul incl. entities and JSON-LD. Flags to the reviewer only (soft): number/scale order, sign, direction words. Not checked by machine: meaning — that is the codex review.
- Adjudication asks at **every occurrence** of a blocked key; a candidate is taken only if all occurrences accept it (A first).
- A review stopped mid-way (`LimitReached`/`CapReached`) carries the finished chunks in `e.partial`; the pipeline records them, so the next run reviews only the rest. `translate` likewise keeps answers already received.
- A claude call that returned no usage (timeout, non-JSON) is charged `runner.UNKNOWN_CALL`; limit/auth answers are charged nothing.
- Unknown Japanese person names are never guessed: the page is held with the names in the reason; add them to `glossary.NAMES` (the glossary file hash is part of the retry key, so the next tick retries).
- The ledger, sidecars and config are **public** (GitHub Pages). Ledger `reason` is a short fixed form (`runner.short_reason`: code + unit ids / names). Full review text goes to `cache_dir/logs/`.

## Runner contract (`runner.tick(root, clone, *, now, cfg, translate, review, cache_dir)`)

- `ja/config.json` — `enabled` (default **false**: the code does nothing until a human flips it), `start` (posts dated on/after it; `null` = none), `max_pages_per_tick`, `weekly_token_budget` (claude in+out per subscription week), `max_review_calls_per_day` (codex review + adjudicate child calls per KST day, default 16), `windows_kst` (hours, 29 = 05:00 next day), `week_reset` (`weekday` Mon=0, `hour`, KST). Missing or malformed → disabled.
- `root` = the human `site/` folder, read only (`reviews/runner.json`); `clone` = fresh origin/main clone; `cache_dir` (default `~/Library/Caches/fdo2a-ja`, env `JA_CACHE_DIR`) holds local state that may be lost at the cost of retranslation: lock, `budget.json`, `limit.json`, `ko_limit.json`, `ko_missing.json`, `auth.json`, `review_calls.json`, `attempts.json`, `tm/`, `logs/`, `chart/`, `last.json`.
- **Missing ≠ corrupt** (`runner.Local`, `CHECKS`): a missing record file is a clean start; unreadable, non-JSON or wrong-shaped (a string token count) is brake `cache_corrupt` — never read as 0, and **never overwritten** (that would lift the brake by itself). `reviews/runner.json` too. A human fixes or deletes the file.
- **Metering**: translate and review calls are wrapped (`_Meter`); every claude call's tokens (and a failed call's `partial`) go to `budget.json` at once, every codex call to `review_calls.json` — a page that dies mid-way still counts. `pipeline.Config.token_cap` = budget left when the page starts.
- **Brakes** (any one → no model calls; zero-call reassembly, notices and deletions still run): outside `windows_kst`; weekly budget spent; own limit until the parsed reset (`review.runner.claude_retry_at`, then `retry_at`, else 5 h); **Korean-side limit** — `reviews/runner.json` `limit_hits` dated this week, a live `correction_blocked_until`, or an `errors` entry of kind 한도 → latched until the next `week_reset`; `cache_corrupt`; **`auth`** (stop `auth` → `auth.json`: rest of the tick stops, 6 h no calls, then one page per tick as a trial; any claude answer clears it, another `auth` re-arms; `ja_local.py retry --auth` clears it now); **`review_cap`** (`max_review_calls_per_day` reached → no new page that KST day; a page in progress stops before its next codex call, `pending`); **`ko_missing`** — `origin/alerts-state:verify_publish.json` (fetched into the clone by explicit refspec, `publish_watch.loads_state`) has a US/KR session `missing`/`missing_quiet` whose deadline passed less than 24 h ago → latched to deadline + 24 h. That signal is auxiliary: unreadable or older than `publish_watch.GITHUB_STALE` → no brake, a 「신호를 못 읽음」 note in `last.json`/digest. Cloud routines' and the contested runner's **limits** leave no local record; these brakes cannot see them. It is not a guarantee that Korean publishing keeps its share.
- **Not built**: resting while the Korean review runner's queue is non-empty — its real pick set is computed inline in `review_gate.cmd_run` (see spec §7).
- Per page: live (`published`/`notice` + file) and inputs unchanged → skip. The retry key is (source blob, deps without `link:`, text hash, renderer, glossary file hash); deps = news data files (blobs), the post's own list item (`list:<json>` hash, not the file), the Korean chart PNG, and `link:<target>` = `"1"`/`"0"` for each in-scope page it links to (`assemble.link_targets`) being live. `build_page(..., live=live set)` sends links to non-live pages to the Korean original; a target publishing or being deleted changes `link:` and reassembles the linker with zero calls (same tick if it went live in the model phase). `link:` keys stay out of the retry key and `expect`.
- Retry: same key already failed → skip, except `review_failed`/`model`/`chart`/`error` (3 per KST day) and `limit`/`budget`/`review_cap`/`auth`/`deferred` (when the brake lifts). The rest (`HUMAN`: `blocking`·`gate`·`doc`·`names`·`fixed`·`news_lang`·`news_malformed`·`missing_units`) waits for a human — the digest marks them 「사람이 풀어야 함」 with how: names → `glossary.NAMES`, fixed → glossary (both change the key), else `ja_local.py retry <path>`. Chart first (deepen a shallow clone once with `--shallow-since`, else hold). Then a zero-call build (stubs raise `NeedModel`); if it needs the model, queue (new pages first, newest first, same day `posts` before `japan/daily`, `news` — link targets first, `max_pages_per_tick`).
- Failure on a live page **whose Korean inputs moved** (source blob, text hash, deps) → `assemble.with_notice` + ledger `notice` keeping the served version's fields; Korean inputs unchanged (glossary/renderer only) → the served page is left alone, no banner, no commit; never-published → `held`/`pending` (a brake-deferred new page is **not** written to the ledger, whatever the brake — no state-only commits on main; it shows in `cache_dir/last.json` only). **Any exception** in one page (`_Tick.guard` first reverts that page's `ja/` files and ledger entry): logged in the report, the tick goes on; a live page whose inputs moved gets the notice with reason `처리 오류`; a model-phase exception counts as attempt `error`. Source deleted → page, sidecar, chart and ledger entry removed. `lists.write` runs whenever anything changed; a list error blocks the push.
- A no-op tick writes and commits nothing (`set_page` bumps `rounds`/`updated` only on a real change).

## Operations

- launchd example: `scripts/ja/com.fdo2a.ja-runner.plist.example` (`runner_launch.py ja run`, every 1800 s). Not installed. `ja_local.py run` reads the snapshot's `ja/config.json` first and exits before cloning when disabled.
- Turning it on, in order: push the code with `enabled: false` → install the plist only once `scripts/ja_local.py` is on origin/main **and the human `site/` folder has pulled `runner_launch.py` with the `ja` entry** (launchd runs that folder's launcher copy; an old one passes `ja run` to `review_gate.py`) (before that the launcher fails every tick; after it, each tick still fetches and snapshots, then exits) → set `start` and `enabled: true` in one commit → after the first page is published, confirm the 「日本語」 buttons point at a non-empty list → next morning check the digest's 일본어판 lines (`verify_digest.py` tail, droppable `Soft` lines).
- `ja_local.py status` shows ledger, attempts and the last tick; `retry <path>` forgets an attempt so the next tick (still under brakes) tries again.
- Tests that enumerate *tracked* files do not see `ja/` until it is committed — open files directly.
- Digest lines (`runner.summary`, `Soft`): corrupt file 「일본어판: 기록 파일이 깨져 멈춤 — <file>」, login 「일본어판: 로그인 만료 — 터미널에서 `claude auth login` …」, unread signals, human holds. Ledger reasons stay short fixed codes (`runner.FIXED_REASON`).

When changing this: read `docs/superpowers/specs/2026-11-14-japanese-edition.md` before touching `scripts/ja/runner.py`, `scripts/ja/publish.py` or the brake/retry rules.
