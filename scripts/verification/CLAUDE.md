# verification — pre-publish gate runner and record

`scripts/run_gates.py` (check / record / verify) runs `config/prepub_gates.json` and writes `verification/<m>/<D>.json` (`prepub-record/2`). Readers (`scripts/review/prepub_view.py`, publish watch, digest) read both `/1` and `/2`.

## Input health (1a, 2026-11-17)

- **Every file in the data roots (`--datadir`, `--tg`, `--stance-next`) is classified** in `config/prepub_inputs.json`: `gate` (a gate reads it — missing, empty, unreadable, stale, failed or unstamped-after-`EFFECTIVE` blocks) / `writer` (writer only — `risk`, `covered_by` recorded) / `unused` / `discontinued` (`approved_by: "user"` only, else config error). **An unclassified file = incomplete.** A new feed is not usable until it is classified.
- Each gate lists its `inputs`; the runner checks them first (`verification/inputs.py`) and does not run a gate whose input is not ok. Checkers also exit 2 themselves on missing input — two layers, keep both.
- States: gate `pass·warn·fail·na·incomplete`; post `verified·conditional·incomplete·failed` (failed > incomplete > conditional > verified). **`na` only when the runner proves "nothing there"** (`na_when`: `collect` ok·`confirmed_none`·`checked`, or before `EFFECTIVE` an independent `legacy_evidence`). Never `na` from an empty list alone.
- **A target list field that is absent or not a list is broken data, not an empty list** — `incomplete_fields`, blocks regardless of `EFFECTIVE` or stamp (checkers `check_auction`·`check_fed`·`check_movers` exit 2 too). Only a present, empty, unstamped list becomes `unconfirmed_empty`.
- Exit: `check`/`record` 0 publishable / 1 violation (rewrite) / 2 incomplete (re-collect once, then hold — never drop a section to publish). `record` 4·5 unchanged.
- `inputs.EFFECTIVE = None` until the collector stamps (`collect`, `_collect_status.json`) are deployed and a first run is confirmed; a human sets the date. **While it is None, 1a is not done**: an empty target list without a stamp is only a condition (`unconfirmed_empty`), and date-less files' freshness and list/txt files' failures are not caught. From `EFFECTIVE`, every collector/reference gate file needs a `_collect_status.json` entry with a sha256.
- **Same-day re-collection**: the workflows run `stamp_collect.py --begin` before collecting and pass `COLLECT_STEPS: ${{ toJSON(steps) }}` to the final stamp, and the same `COLLECT_RUN_ID` to both — the stamp uses a begin record only when its run id matches (else `run: unknown`); every ledger entry gets `run` (`written`·`skipped`·`kept` ok / `failed` / `unknown`·`untracked`). A file the run did not rewrite although its step ran is `status: failed`, `run: failed`, old bytes under `stale_copy` — the ledger beats the old copy's in-file `collect: ok`. From `EFFECTIVE` that blocks (`failed`), and a ledger entry whose `run` is not ok is `unstamped`; before it, condition `recollect_failed`. Step ids in the workflows must match `stamp_collect.STEP_OF`; a collector that swallows an exception calls `collect_status.note_run_failure`.
- **`accepted_missing`** = "an indicator the official agency did not publish is conditionally left out of verification", never "a failed collection is tolerated". Per-file list in `config/prepub_inputs.json`: `id`·`key`·`fred_id`·`transform`·`ref_period` (YYYY-MM)·`lacking` (YYYY-MM)·`reason`·`source`·`approved_by: "user"`·`approved_on`·`expires`·`impact` (`affects_checks`·`sections`·`scores`), else config error. Only when `collect.status` is `partial`, **every** `collect.missing` key is registered, the post date is `≤ expires` (`approved_on` is a record only) and `collect.missing_ref[key]` equals the registration's `fred_id`·`transform`·`ref_period` **and its `lacking` is exactly the registered month** (`["2025-10"]` — the comparison month the source does not have; another or several months = another cause) — name alone never matches — the file is conditional (`accepted_missing`; id, indicators, approval date, expiry, impact and cause in the record and alert) instead of incomplete. Anything else — a third miss, `failed`, stale, another month — blocks. The original `collect` is never rewritten and no value is substituted. **Exactly one exception is registered (user-approved 2026-11-17): `us-2026-10-cpi-yoy-not-published` — CPI YoY (CPIAUCSL·yoy_pct) and Core CPI YoY (CPILFESL·yoy_pct), ref 2026-10, expires 2026-12-09, no auto-renewal**, registered on the four files the gap travels through (`econ_indicators` `no_value:<n>` → `macro_metrics` `econ:…` → `macro_eval`·`releases/index` `metrics:econ:…`, `collect_status.carry_upstream`); a test pins the policy to exactly that. The list is a permission-separation target — today a routine can still edit it. `macro_metrics.json` carries `coverage` for any axis where a defined scored indicator was not used (M = scored indicators defined for the axis in `ECON`; every unused one listed with its reason `no_value`·`no_score`·`introduced`·`no_row`, and `no_score:`/`introduced:` keys go into `collect.missing`, so a mixed day gets no exception); the post must show it (`data-axis-coverage`, `check_macro`), and `check_macro` exits 2 (hold, reason 「승인된 결측이 판단을 바꿀 수 있음 — 사람 승인 필요」) when the left-out indicators at either end of the score range (`us.macro_metrics.SENSITIVITY_Z`) would change the axis direction, strength or regime leg. There is no human-approval path yet — it stays held.
- Post-publish rechecks (corrector, style pass, digest): `--recheck`, `--legacy-releases` and "original also exited 2" apply only to posts before `inputs.STRICT_FROM` (must equal the deploy date). **One rule decides it: `inputs.legacy_post(path)`** — the basename must be exactly `YYYY-MM-DD.html`; any other name gets no legacy verdict. Checkers call `inputs.legacy_recheck`; `review/corrector.py` and `review/style_pass.py` call the same function (fallback copies for an isolated checkout, tied by a test).
- Not solved here: a routine can still edit the policy, data or gates (permission separation is a later stage). Warnings still do not block (no `auto_ok` yet). Do not write that publishing is proven safe.

When changing this: read `docs/superpowers/specs/2026-11-17-input-health.md` before touching `inputs.py`, `record.py`, `config/prepub_inputs.json` or a checker's exit codes, and run `scripts/verification/tests/test_input_mutations.py`.
