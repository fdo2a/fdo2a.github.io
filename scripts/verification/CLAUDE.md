# verification — pre-publish gate runner and record

`scripts/run_gates.py` (check / record / verify) runs `config/prepub_gates.json` and writes `verification/<m>/<D>.json`. Readers (`scripts/review/prepub_view.py`, publish watch, digest) read both `prepub-record/1` and `/2`.

## The switch — everything below is OFF until `inputs.EFFECTIVE` is a date (2026-11-20)

- **One function decides: `verification.inputs.enforcing()`** (`EFFECTIVE is not None`). Nothing else reads `EFFECTIVE`. `review/corrector.py`·`review/style_pass.py` keep a copy `STRICT_FROM` for isolated checkouts (a test ties them).
- **While it is None every verdict equals pre-1a main**: checkers keep their old exits (most carry the old `main()` as `_main_pre1a`), `run_gates` runs `_main1` with `record.py` (the pre-1a file, byte-identical — `prepub-record/1`), the coverage and `previous_why` rules do not run, recheck flags are not passed, and every post is a legacy post. Only the collector side is live: `collect` fields and `_collect_status.json`. Two collector changes that alter existing values also wait: the econ row with no previous (`collect_market_data._econ_pair`) and dropping the prior-session tail from KR intraday (`kr.sources.dated_30min`).
- **Turning it on** = set `EFFECTIVE` and both `STRICT_FROM` copies to the first enforced post date, after the first stamped collections are confirmed. From that date: 2판 runner `_main2` + `record2.py`, exit 2 = incomplete, unstamped = incomplete, and only posts before it get legacy rechecks. The orchestrator·writer wording for exit 2 and the coverage marker must land the same day.
- A new blocking rule goes behind `enforcing()` with the pre-1a behaviour kept verbatim in the other branch, and a case in `tests/test_switch_off.py`. Tests of the on-state run with `PREPUB_INPUTS_TEST_STRICT_FROM` (set by `scripts/conftest.py` for the listed modules and `*_1a.py`; it can only turn the switch on).

## Input health (1a, 2026-11-17)

- **Every file in the data roots (`--datadir`, `--tg`, `--stance-next`) is classified** in `config/prepub_inputs.json`: `gate` (a gate reads it — missing, empty, unreadable, stale, failed or unstamped-after-`EFFECTIVE` blocks) / `writer` (writer only — `risk`, `covered_by` recorded) / `unused` / `discontinued` (`approved_by: "user"` only, else config error). **An unclassified file = incomplete.** A new feed is not usable until it is classified.
- Each gate lists its `inputs`; the runner checks them first (`verification/inputs.py`) and does not run a gate whose input is not ok. Checkers also exit 2 themselves on missing input — two layers, keep both.
- States: gate `pass·warn·fail·na·incomplete`; post `verified·conditional·incomplete·failed` (failed > incomplete > conditional > verified). **`na` only when the runner proves "nothing there"** (`na_when`: `collect` ok·`confirmed_none`·`checked`, or before `EFFECTIVE` an independent `legacy_evidence`). Never `na` from an empty list alone.
- **A target list field that is absent or not a list is broken data, not an empty list** — `incomplete_fields`, blocks regardless of `EFFECTIVE` or stamp (checkers `check_auction`·`check_fed`·`check_movers` exit 2 too). Only a present, empty, unstamped list becomes `unconfirmed_empty`.
- Exit: `check`/`record` 0 publishable / 1 violation (rewrite) / 2 incomplete (re-collect once, then hold — never drop a section to publish). `record` 4·5 unchanged.
- `inputs.EFFECTIVE = None` until the collector stamps (`collect`, `_collect_status.json`) are deployed and a first run is confirmed; a human sets the date. **While it is None, 1a is not done**: an empty target list without a stamp is only a condition (`unconfirmed_empty`), and date-less files' freshness and list/txt files' failures are not caught. From `EFFECTIVE`, every collector/reference gate file needs a `_collect_status.json` entry with a sha256.
- **Same-day re-collection**: the workflows run `stamp_collect.py --begin` before collecting and pass `COLLECT_STEPS: ${{ toJSON(steps) }}` to the final stamp, and the same `COLLECT_RUN_ID` to both — the stamp uses a begin record only when its run id matches (else `run: unknown`); every ledger entry gets `run` (`written`·`skipped`·`kept` ok / `failed` / `unknown`·`untracked`). A file the run did not rewrite although its step ran is `status: failed`, `run: failed`, old bytes under `stale_copy` — the ledger beats the old copy's in-file `collect: ok`. From `EFFECTIVE` that blocks (`failed`), and a ledger entry whose `run` is not ok is `unstamped`; before it, condition `recollect_failed`. Step ids in the workflows must match `stamp_collect.STEP_OF`; a collector that swallows an exception calls `collect_status.note_run_failure`.
- **One run**: the ledger carries `run_id` and `report_date` (from `EFFECTIVE` it must be this post's session and have a run id), the record carries `collect_run` (the ledger's run id, session, sha256) next to `post.sha256` and `inputs.files`, and `verify` compares all three with the disk — a ledger from another run is "수집 실행이 다르다" (exit 1, re-record).
- **Missing-value states** (`us.macro_metrics.MISSING_STATES`): `not_published` (source row present with an **explicit** blank — API `"."`, CSV empty or `.`; a missing/null/odd value field is `unclear_dates` → `unknown`) / `not_collected` (no such row) / `collect_failed` / `unknown` (no basis — never guessed, holds). A row whose `previous` is null carries `previous_why`; the table cell is `— (미발표|미수집|수집 실패|확인 불가)` and `macro_table_gate` checks the reason.
- **`accepted_missing`** = "an indicator the official agency did not publish is conditionally left out of verification", never "a failed collection is tolerated". Per-file list in `config/prepub_inputs.json`: `id`·`key`·`fred_id`·`transform`·`ref_period` (YYYY-MM)·`lacking` (YYYY-MM)·`reason`·`source`·`approved_by: "user"`·`approved_on`·`expires`·`impact` (`affects_checks`·`sections`·`scores`), else config error. Only when `collect.status` is `partial`, **every** `collect.missing` key is registered, the post date is `≤ expires` (`approved_on` is a record only) and `collect.missing_ref[key]` equals the registration's `fred_id`·`transform`·`ref_period` **and its `lacking` is exactly the registered month** (`["2025-10"]` — the comparison month the source does not have; another or several months = another cause) **in state `not_published`** (`lacking_why`) — name alone never matches — the file is conditional (`accepted_missing`; id, indicators, approval date, expiry, impact and cause in the record and alert) instead of incomplete. Anything else — a third miss, `failed`, stale, another month — blocks. The original `collect` is never rewritten and no value is substituted. **Exactly one exception is registered (user-approved 2026-11-17): `us-2026-10-cpi-yoy-not-published` — CPI YoY (CPIAUCSL·yoy_pct) and Core CPI YoY (CPILFESL·yoy_pct), ref 2026-10, expires 2026-12-09, no auto-renewal**, registered on the four files the gap travels through (`econ_indicators` `no_value:<n>` → `macro_metrics` `econ:…` → `macro_eval`·`releases/index` `metrics:econ:…`, `collect_status.carry_upstream`); a test pins the policy to exactly that. The list is a permission-separation target — today a routine can still edit it. `macro_metrics.json` carries `coverage` for any axis where a defined scored indicator was not used (M = scored indicators defined for the axis in `ECON`; every unused one listed with its reason `no_value`·`no_score`·`introduced`·`no_row`, and `no_score:` keys go into `collect.missing`, so a mixed day gets no exception; `introduced` — the row's own flag true, latest value and score present — is a scoring rule, not a gap: it stays out of `missing`, `check_macro` prints a 경고 line (post conditional) and holds only if adding the row's **actual score** changes the axis direction or regime leg (strength alone is a note) or the row is still introduced against an older book than yesterday's); the post must show it (`data-axis-coverage`, `check_macro`), and `check_macro` exits 2 (hold, reason 「승인된 결측이 판단을 바꿀 수 있음 — 사람 승인 필요」) when the left-out indicators at either end of the score range (`us.macro_metrics.SENSITIVITY_Z`) would change the axis direction, strength or regime leg. There is no human-approval path yet — it stays held.
- Post-publish rechecks (corrector, style pass, digest): `--recheck`, `--legacy-releases` and "original also exited 2" apply only to posts before `inputs.strict_from()` (= `EFFECTIVE`). **One rule decides it: `inputs.legacy_post(path)`** — the basename must be exactly `YYYY-MM-DD.html`; any other name gets no legacy verdict. Checkers call `inputs.legacy_recheck`; `review/corrector.py` and `review/style_pass.py` call the same function (fallback copies for an isolated checkout, tied by a test).
- Not solved here: a routine can still edit the policy, data or gates (permission separation is a later stage). Warnings still do not block (no `auto_ok` yet). Do not write that publishing is proven safe.

When changing this: read `docs/superpowers/specs/2026-11-17-input-health.md` before touching `inputs.py`, `record2.py`, `config/prepub_inputs.json` or a checker's exit codes, and run `scripts/verification/tests/test_input_mutations.py`.
