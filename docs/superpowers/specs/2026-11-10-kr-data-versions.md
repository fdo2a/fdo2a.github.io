## 사용자 결정(2026-11-09·11-10)

- 범위는 KR. 판 식별 형식은 시장에 묶지 않는다. US 덮어쓰기는 별도 위험으로 남긴다.
- 발행판은 동결하고, 재수집판은 따로 보관한다. 재수집은 막지 않는다. 새로 모은 값이 검증된 값을 **자동으로 대체하지 못하게** 한다.
- 주간 기본값 = 일간 발행판.
  - 수급 = 다음 거래일 관측값(「공식 확정」 표기 금지).
  - 업종 = 「주간 업종별 일간 등락률 평균」(발행판 값만 쓴다. 결측은 0 이 아니라 관측 거래일 수로 표시하고, 18시대 값과 새벽 값을 섞지 않는다).
  - 지수 = 원자료 오류를 확인했을 때 수동으로 정정한다.
- 2단계로 나눈다. **1단계는 수집기만 바꾼다**(루틴의 작성·검증 기록·push 절차는 그대로). 최우선 조건은 기존 정상 발행을 깨뜨리지 않는 것이다.
- 발행 때 지수가 빠진 날: 새벽 값으로 자동 보완하지 않는다. 주간 발행을 보류하고 수동으로 정정한다. 이 보류는 **의도한 무결성 통제**다. codex 16회 지적(새 중단 경로)은 맞다 — 오늘 구조는 재수집이 지수를 채우면 주간이 나갈 수 있다. 「끝값 = 마지막 발행본 종가」 검사는 코드가 아니라 `WEEKLY_ORCHESTRATOR.md` 지시문에만 있다. 오늘보다 중단이 얼마나 늘어나는지는 회귀 시험으로 확인한다.
- 폴백이 돌면 보호가 꺼진 것이다. 기록하고 경고하며, 동결 성공으로 세지 않는다.

## 무엇을 하나(1단계)

**고정 경로에 대해 바뀌는 규칙은 하나다.** 이 실행의 거래일 D 가 원격에서 이미 발행됐으면(`origin/main:kr/posts/<D>.html`) D 에 딸린 고정 경로를 이 실행 값으로 바꾸지 않는다. 그 밖의 새 동작은 별도 경로에 기록만 한다.

1. **실행 원본** — 매 실행이 `versions/kr/<D>/runs/<run_id>/` 에 그 실행의 KR 산출물 전부와 `manifest.json` 을 저장한다. manifest 에는 파일별 sha256, 바뀜/같음/삭제, field_status(yfinance 지정 거래일 봉 확인), 수집 시각(KST·UTC), trigger, 발행판 대비 diff 를 적는다. 폴더는 추가만 하고, 이미 있으면 실패한다. `run_id` = `<UTC>-gh<RUN_ID>.<ATTEMPT>` 또는 `local-<uuid4>`.
2. **커밋 절차**(워크플로 마지막 단계 `versions.py commit`, Actions 밖에서는 `--scratch-checkout` 없이 거부):
   - 오늘의 Commit data 와 같은 add 줄(`versions_kr.STAGE_SH`, bash -e)로 로컬 커밋 O 를 만든다. 그 전에 작업 트리의 산출물을 `$RUNNER_TEMP/versions/` 에 저장한다(artifact, 90일).
   - **임시 git worktree** 에 원격 최신을 펼치고, fetch → 판정 → 재구성 → push 를 한 번 시도한다. 원래 작업 트리는 건드리지 않는다. 거절되면 원격에서 다시 시작한다(최대 5회).
   - **실패 정책**(사용자 11/10):
     - shadow → `reset --soft O^` + 수정하지 않은 `push_with_retry.sh`(오늘과 같다). 폴백 기록 `versions/kr/<D>/fallback/<run_id>.json`(기록 실패는 무시)과 `::warning::` 을 남긴다. 보호가 꺼진 실행이라 동결 성공으로 세지 않는다.
     - enforce·발행됨(원격 최신 기준. fetch 를 한 번도 못 했으면 job 시작 checkout 기준) → **반영 보류**: push 하지 않고 `::warning::versions hold` 를 낸다.
     - enforce·미발행 → **보호 폴백**: 매 시도마다 fetch(못 하면 보류)하고, 그 사이 발행됐으면 보류한다. 아니면 O 를 원격 위에 올리고, 발행일 지수 빈 칸 보류를 적용해 push 한다. 폴백 자신이 실패하면 push 없이 exit 1 로 끝낸다. **enforce 에는 무보호 경로가 없다.**
3. **발행된 D 의 동결(enforce 모드)** — P = `kr/posts/<D>.html` 을 처음 들인 커밋.
   - 날짜 없는 고정 경로 파일: 원격 최신 그대로 둔다(그 사이 D+1 이 반영됐을 수 있다).
   - `_sessions[D]` 의 industry·top_value·leading_industries 는 P 트리에서 `session_from` 으로 함께 계산한 값이다. 빈 곳은 빈 채로 둔다.
   - 수급은 시장별로 원격 기존 값 > P 트리 값.
   - 원장 D 행은 P 트리 값이다.
   - news·telegram·차트의 D 파일은 P 트리 그대로 둔다.
   - 승격(promotions/)은 맨 마지막에 그 주 전체에 다시 적용한다.
   - D 이전 날짜의 extra_flows(다음 거래일 관측 수급)는 오늘처럼 반영한다 — 예외로 덮어쓰는 것이 아니라 처음부터 다른 선택 정책이다.
   - P 를 못 찾으면 오늘처럼 이번 실행 값을 쓰고 `filled_from: run` 을 남긴다.
4. **발행판 보관** — 아직 없는 최근 10거래일마다 `versions/kr/<D>/published/` 를 만든다. P 트리의 산출 파일을 복사하고, `published.json` 에 P·글 sha256·기록 경로·파일 sha256 을 적는다. `verify-published` 는 기록(`verification/kr/<D>.json`)의 `repo:` 입력 전부를 P 트리 blob 과 대조한다. `workspace-only` 는 「복원 불가」, 불완전 기록은 「부분」으로 표시하고 발행은 막지 않는다.
5. **수동 승격** — `versions.py promote --date D --field <필드> --from <run_id|value> --reason`. 사람이 로컬에서 부른다(Actions 안에서는 거부, 수집·루틴은 부르지 않는다). 지수 값은 현재 원격의 `kr/posts/<D>.html` 본문에서 **그 지수 이름 바로 다음 수치**가 소수 둘째 자리까지 같아야 받는다(주석·속성 제외, 사이에 다른 지수명이 있으면 거부). 없으면 「글 정정이 먼저」를 내고 거부한다. 승격 기록(원본 manifest·읽은 파일·정정된 글의 sha256), 대상 갱신, 그 주 재계산을 임시 worktree 에서 한 커밋으로 push 한다. 승격은 enforce 재구성의 맨 마지막에 다시 적용된다. shadow 는 승격을 적용하지 않으므로 그동안에는 쓰지 않는다.
6. **지수 누락 표시·보류** — `finalize` 는 세션 날짜 × 지수 빈 칸을 `missing` 에 `indices.<지수>.<날짜>` 로 기록만 한다(`complete` 불변 — shadow·미발행일의 일시 결측은 오늘과 같다). enforce 는 **발행된 날**의 빈 칸이 있으면 주간 `complete=false` 로 보류한다(`versions_kr.hold_published_gaps` — 원장·세션 날짜로 직접 계산하고, 보호 폴백에서도 적용). 매일 검증 알림이 그 키를 한 줄로 알린다.
7. **텔레그램 커서** — 다음 거래일 수집의 직전 커서는 「발행판 D 파일과 D 의 runs/ 텔레그램 가운데 채널별로 가장 앞선 ok 커서」다.
8. **모드** — `KR_VERSIONS_MODE` = `shadow`(기본값: 원본·판정·발행판 기록만 남기고 고정 경로는 오늘과 같은 바이트) | `enforce`(동결). 바꾸려면 사용자 확인이 필요하다.

## 하지 않는 것(2단계·별도)

- 루틴 작성 중 덮어쓰기·수동 force·직접 수집 폴백의 동결 우회(오늘과 같음)
- 작성 입력 스냅샷, 결측 변환, 주간 새 규칙 전환(1c — 그림자 뒤 사용자 확인)
- 금요일 수급(주 경계를 넘지 못한다)
- 업종 기준 시각 정의, 휴장 달력 2027, 레포 밖 백업, 업종 60/79 범위
- W45 소급
