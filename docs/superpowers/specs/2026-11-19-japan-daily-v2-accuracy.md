# 일본 일간 v2 — A. 정확성 (2026-11-19)

이 spec 은 codex 설계 검토 17회차에서 DESIGN OK 를 받은 설계 20판과 B·C 방향 개요를 그대로 옮긴 것이다. 구현은 `feat/jp-daily-v2`.

## 사용자 결정 (2026-11-19)
- 목적: 일본 주식에 대한 독립 투자 리서치. 일간 = 오늘 무엇이 달라졌고 기존 판단에 어떤 영향을 주는가, 주간 = BOJ 정책 경로·거시·엔 구조적 수급·해외 자금.
- 순서 A(정확성) → B(평소와의 차이) → C(판단 기록·복기). A 가 실제 발행에서 정상 동작한 뒤 B 상세 설계, B 가 안정된 뒤 C.
- 원칙: **계산 가능한 사실은 코드가 생성하고, AI 는 검증된 사실을 해석하는 역할만 맡는다.** 7회 연속 설계 NOT OK 의 원인을 「자유 서술을 사후 문자열 규칙으로 검증하는 구조」로 판정하고 A 를 줄여 다시 설계했다(8회차~).
- 자동 문단 삭제 없음. 작성 재시도 4회는 문장 수정에만, 4회 실패 = 발행 중단 + 경보. 데이터 누락은 수집 단계에서 블록 제외.
- 하지 않는다: 예상치, 검증되지 않은 경기 국면 점수, 근거 없는 지수 기여도, ETF 이력과 지수 이력 연결, 관측치가 모자란 지표.
- **원천 약관은 사용자 지시(「그냥 무시하고 진행해」)로 기술 검토에서 분리했다. 공개 재배포 권한을 확인했다는 뜻이 아니며 미해결 사항이다.** 근거 문서: JPX 사이트 약관(축적·가공·재배포 금지), JPX 지수 라이선스(종가 외부 배포는 원칙적으로 허락 필요), 네이버 비공식 API, Yahoo!ファイナンス 자동 취득 금지 문구(기존 일본 뉴스 수집 포함).

## 실측 근거 요약
- 1306 ETF 와 실제 TOPIX: 발행 15세션 중 4일 ≥0.5%p, 11/04 ETF +0.24% vs TOPIX −0.89% — 시장가가 NAV 보다 1.05% 비싸게 끝난 것(수집 오류 아님). 업종 ETF 하루 거래대금 800만~9,700만 엔, 11/18 17개 중 13개가 지수와 ≥0.2%p.
- JPX 슬롯 11/18 값 = 사용자 대조 7개 일치. 네이버 `.TOPX/day` 6세션 종가가 JPX 와 일치. 일경 CSV 949행(2023-01-04~).

## 기존 한계 (A 가 풀지 않는다)
- 작성자 산문 숫자는 「스냅샷 어딘가에 있는가」 로만 본다(닛케이·엔·금리 수준·개별주·매크로 공통, 전일 종가 == 당일 종가인 날 포함). 후속: 기존 필드도 `facts` 로 옮겨 문장이 가리키는 지표·관측일에 맞는 값인지 확인.
- 숫자 없는 정성 서술, 손 채움 일정표의 발표 연기·취소.

# 일본 일간 v2 설계 (20판) — A. 정확성 (줄인 판)

작성 2026-11-19. 11판 = 8회차 7건 반영, 12판 = 생성 문장 내용 고정(§4)과 되돌리기 가드(§6-3), 13판 = 9회차 6건 반영, 14판 = 10회차 3건 + 9판 대조로 되살린 조건 7개(R1~R7, 본문에 표시). 15판 = 11회차 7건(되살린 조건 R8~R12 + 신규 2건). 16판 = 12회차 5건(R13·R14 + 반올림 둘 + 조상 검사). 17판 = 13회차 2건(방향은 값의 차로, 조립기가 붙인 id 허용). 18판 = 14회차 2건(변화의 부호를 스냅샷에 고정, 뉴스 절의 작성자 글도 검사). 19판 = 15회차 1건(기사 블록 안의 작성자 글). 20판 = 16회차 1건(생성 문장과 기존 게이트·조판의 충돌). 사본 `jp_daily_v2_design.ed{10,…,19}.md`.

## 원칙 (사용자, 2026-11-19)
**계산 가능한 사실은 코드가 생성하고, AI 는 검증된 사실을 해석하는 역할만 맡는다.** 7회 연속 NOT OK 의 원인은 자유 서술을 사후 문자열 규칙으로 검증하는 구조였다. 그래서 10판은 작성자가 TOPIX·업종지수·금리 스프레드의 수치와 방향을 **쓰는 자리를 없앤다.** 코드가 문장까지 만들고, 게이트는 그 문장이 코드 출력과 바이트로 같은지만 본다.

고정된 결정: 순서 A→B→C. 컨센서스·지수 기여·ETF 이력과 지수 이력 잇기 금지. 약관·재배포 권한은 사용자가 알고 진행한다(확인했다는 뜻이 아니다 — 미해결).

## 1. 구조 한눈에

| 항목 | 10판 |
|---|---|
| TOPIX·업종지수 | JPX 값(+네이버 대조)에서 코드가 표와 사실 문장 생성. ETF(1306·1617~1633) 수집 제거 |
| 금리 스프레드 수치·방향 | 코드가 문장 생성. 작성자는 다시 쓰지도 방향을 바꾸지도 못한다 |
| 숫자와 날짜 | 새 데이터는 `facts`(`field_id·observation_date·value·unit·source_id·status`)로 구조화 |
| 작성자 재시도 | 4번(조립 실패 포함, 지금 계약 그대로). 다 실패하면 **발행 중단 + 경보**(지금처럼) |
| 자동 문단 삭제 | 제거함 |
| 실행 간 기록 혼입 | `run_id` 로 격리, 명시 경로만 스테이징(§6) |

## 2. 데이터 검증 (코드 생성이 검증을 대신하지 않는다)

**JPX 지수 파일** `www.jpx.co.jp/market/indices/indices_stock_price3{,.1~.5}.txt` + `.time.txt`(값 파일에 날짜가 없다).
1. **쌍 읽기**: 시각 → 값 → 시각. 세 응답 HTTP 200, 앞뒤 시각 문자열이 같고 `^\d{12}$` 이며 **실재하는 `Asia/Tokyo` 일시로 풀린다(R2)**, 값 응답과 **뒤(두 번째) 시각 응답**의 `Last-Modified` 가 둘 다 있고 2초 이내(R9), 값 파일은 중복 키 없는 JSON(`utf-8-sig`). 어긋나면 2초 간격 3번까지, 그 뒤엔 읽지 못한 것.
2. **세션으로 슬롯 고르기**: 6개 슬롯의 시각으로 `슬롯→날짜(JST)` 표를 만들고(404·형식이 다른 슬롯은 뺀다) 날짜가 `session` 인 슬롯(target)과 `prev_session` 인 슬롯(prev)을 **각각 정확히 하나** 고른다. 파일 번호로 고르지 않는다. **고른 두 슬롯을 쌍 읽기로 읽은 뒤, 그 쌍의 시각이 표의 시각과 글자 그대로 같고 날짜가 각각 `session`·`prev_session` 인지 다시 본다(R1 — 10회차 #1: 표를 만든 뒤 09:00 JST 에 슬롯이 밀리면 `.1` 이 다른 날이 된다. 줄이면서 빠졌던 9판 조건).** 겹치거나 다시 본 시각이 다르면 표부터 2번까지 다시. **그래도 겹치거나 다르거나, target·prev 가 없으면(분모가 5개 슬롯 밖 등) TOPIX·업종 둘 다 `invalid`(R3).**
3. **값과 연쇄 검산**: 숫자는 쉼표를 지워 **`Decimal` 로 읽고 `float` 를 거치지 않는다(R9** — 4,000.00 → 3,873.00 은 정확히 −3.175% 인데 `float` 반올림은 −3.17, 원천은 −3.18 이다). 값이 유한한 수여야 하고 **양일 종가(`currentPrice`)는 양수**여야 한다(`--`·빈 값·0·음수는 실패). 그다음 `|current − previousDayComparison − prev.current| ≤ 0.01` 이고 **원천 `previousDayRatio` 가 `(cur/prev−1)×100` 을 `Decimal` 로 소수 둘째까지 `ROUND_HALF_UP`(절댓값 기준 사사오입: −3.175 → −3.18) 한 값과 정확히 같아야** 한다(12회차 (b)1 — 허용차 0.005 는 경계에서 −3.17 과 −3.18 을 둘 다 통과시켰다). JPX 가 경계에서 어느 쪽으로 반올림하는지는 실측하지 못했다 — 다르면 그날 그 블록이 `invalid` 가 될 뿐 틀린 값이 실리지는 않는다.
4. **네이버 독립 대조**(TOPIX, 허용차 0.01) — 경로는 JPX 슬롯이 정한다. target 이 현재 슬롯이면 `/index/.TOPX/basic` **만**: `localTradedAt` 이 **오프셋 달린 ISO 시각이고(R4)** 그 JST 날짜 == session, `marketStatus == CLOSE`, 종가와 (종가 − 전일비)가 JPX 종가·분모와 일치. **날짜가 다르거나(앞이든 뒤든) `CLOSE` 가 아니면 실패이고 `/day` 로 넘어가지 않는다(R4).** target 이 `.N` 이면 `/chart/foreign/index/.TOPX/day` 만: session 행·prev_session 행이 각각 정확히 하나이고 두 종가 일치.
5. **업종 키 17개**가 정해진 집합과 정확히 같다 — **업종 블록의 조건이다.** 키가 빠지거나 남으면 업종만 무효이고, 독립 대조를 통과한 TOPIX 는 그대로 싣는다(9회차 #3: 업종 쪽 결함이 정상 TOPIX 를 지우면 안 된다). 두 블록을 함께 무효로 하는 것은 공통 조건(1·2·6)이 실패할 때뿐이다.
6. **마감 뒤의, 갱신이 멈춘 최종판만**(8회차 #1, 9회차, R8): **계산에 쓰는 두 슬롯(target·prev) 모두** 슬롯 시각이 16:30 JST 이상이어야 한다(실측 6세션의 마지막 시각이 전부 16:59. 9판의 「15:30 이전 거부」 를 두 슬롯 모두에 되살리고 하한을 올렸다 — 분모 슬롯이 15:29 장중판이면 연쇄 검산이 맞아도 거부). target 이 현재 슬롯이면 추가로 값 응답의 `Date − Last-Modified ≥ 30분`(장중에는 1분마다 갱신된다). 못 채우면 TOPIX·업종 모두 `invalid`. 15:30~16:59 사이 실제 값 변화는 실측 전이라, 첫 2주는 수집 로그의 슬롯 시각을 본다.
7. 휴장일·주말 세션이면 수집기가 후보를 만들지 않고 `SKIP`.
- 발행 값: 종가 = target, 분모 = prev(`prev_session` 날짜 그 값만), 등락률 = 위 검산을 통과한 원천 `previousDayRatio`(소수 둘째). 다른 원천·ETF·전일 값으로 물러서지 않는다.

**JGB**: 지금 계약 그대로(네이버 지표물 전 만기 한 날짜·전부 아니면 무, 실패하면 블록째 MOF 직전 세션, 두 원천 사이 bp 금지). 스프레드는 같은 블록의 두 다리로만 계산한다: `s2s10 = 10Y − 2Y`, `s10s30 = 30Y − 10Y`, 변화는 **검증된 원시 호가를 원문 글자에서 `Decimal`(1만분의 1 %p 정수)로 읽어 — `float` 를 거치지 않는다 — 양일 스프레드를 각각 구해 뺀 뒤 마지막에 한 번만** 소수 첫째로 `ROUND_HALF_UP`(절댓값 기준) 반올림한다(12회차 (b)2 재현: 10Y 2.7000→2.7035·2Y 불변이면 정확히 +0.35bp → +0.4bp 인데 `float` 로는 0.34999…→ +0.3bp). 수준 `spread_bp` 도 같은 방식(두 다리의 `period`·`prev_period`·`source` 가 같을 때만). 만기별 `chg_bp`(이미 반올림된 값)의 차로 구하지 않는다 — 8회차 #2 재현: 2Y 1.8800→1.8804, 10Y 2.7880→2.7876 이면 다리별 0.0·−0.0 이라 「같았다」 가 되지만 실제는 −0.1bp. 그래서 `jgb_naver`·`jgb_block` 이 원시 값을 함께 넘긴다.

## 3. 데이터 상태와 `facts`

수집기가 2판 스냅샷(`"schema": 2`)에 `facts` 를 쓴다. 한 항목 = `{field_id, observation_date, prev_observation_date(변화 값만), value, unit, source_id, status}`.
- **변화 값은 부호를 함께 고정한다**(14회차): `*.chg_pct`·`*.chg_bp` 항목마다 `direction`(+1·0·−1 — 반올림 **전** 차의 부호. TOPIX·업종은 `종가 − 분모`, 스프레드는 `Decimal` 원시 변화)을 수집 때 스냅샷에 쓴다. 조립·게이트는 표시값(`value`)에서 방향을 다시 계산하지 않고 `direction` 만 읽는다 — 그래서 +0.04bp(표시 0.0, `direction` +1)와 정확한 0(`direction` 0)이 조립 단계에서 갈린다. `sector.breadth.*` 도 `direction` 으로 센 값이다.
- `field_id`: `topix.close`·`topix.chg_pct`, `sector.<JPX 키>.close`·`.chg_pct`(17개), `sector.breadth.up`·`.down`·`.flat`, `jgb.<만기>.yield`·`.chg_bp`, `curve.<s2s10|s10s30>.spread_bp`·`.chg_bp`.
- `source_id`: `jpx:price3`(또는 `jpx:price3.N`), `naver:jgb`, `mof:jgb`. **계산 근거를 함께 고정한다(R11)**: TOPIX·업종의 변화 값마다 실제 분모 `denom {date, value, source_id}`, 그리고 블록마다 **양일 슬롯 각각의** `{slot, jpx_time, last_modified, sha256(값 파일 원문)}`, TOPIX 에는 네이버 대조 근거 `xcheck {via, close, prev_close, traded_at}`. 원문 파일은 커밋하지 않는다. **이 근거들(분모·슬롯 근거·`xcheck`)은 전부 `facts` 키 아래에만 둔다(R13)** — §5-3 이 `facts` 를 통째로 작성자 허용 수치 집합과 `data-ref` 대상에서 빼므로, `xcheck.prev_close` 의 3,840.02 같은 숫자가 산문에서 허용되는 일이 없다. 스냅샷의 다른 자리에 새 데이터의 숫자를 복사하지 않는다(시험: 2판 후보에서 `facts` 를 지운 나머지에 TOPIX·업종·스프레드 값이 하나도 없다).
- **`status`**
  - `current`: 검증을 다 통과했고 `observation_date == session`.
  - `stale`: 값은 정상인데 관측일이 과거(MOF 폴백 JGB — 직전 세션 값).
  - `invalid`: 출처·값·단위·날짜 검증 실패. `value` 는 `null` — 실패한 숫자를 스냅샷 어디에도 남기지 않는다(사유는 `fetch_status` 에 글자로만, 숫자 없이).
- 업종은 **JPX 키로** 맞춘다(이름은 반각 `･` 가 섞여 있다). 키 17개와 한국어 이름표는 9판 A3 의 목록 그대로(R5).
- **블록 규칙**: TOPIX 는 2절 1~6 이 전부 통과해야 `current`, 아니면 `invalid`(`stale` 로 싣는 경우는 없다 — 전일 TOPIX 를 오늘 자리에 쓰지 않는다). 업종은 TOPIX 가 `current` 이고 17개 전부 값·연쇄 검산을 통과해야 블록이 `current`, **하나라도 실패하면 17개와 breadth 전부 `invalid`**. 커브는 구간별: 두 다리가 네이버 당일이면 `current`, MOF 폴백이면 `stale`, 다리나 변화가 없으면 그 구간만 `invalid`.
- **당일 변화 문장은 `current` 로만 만든다.**
- `stale` 커브는 **변화 분석을 뺀다**(날짜를 밝힌 변화 문장을 만들지 않는다). 이유: 폴백일에는 JGB 표가 이미 기준일을 달고 수준을 보이고, 「11월 17일 기준 변화」 문장은 「오늘의 장」 을 다루는 글에서 당일 변화로 읽힐 여지를 남긴다. 빼는 쪽이 단순하고 틀릴 길이 없다.
- 닛케이·엔·콜·매크로·개별주는 지금 구조 그대로다(`facts` 로 옮기지 않는다 — 회귀 위험을 만들지 않으려는 것이고, 옮기는 일은 아래 「기존 한계」 의 후속 작업이다). `complete` 는 지금처럼 닛케이만으로 정한다.
- 옛 필드 `indices.topix_etf`·`sectors`·`sector_breadth` 는 2판에서 쓰지 않는다. `denom` 은 2판 스냅샷의 허용 수치 집합에서 뺀다. **게이트의 ETF 코드 예외(`_EXTRA_OK` 의 `1306·1617·1633`, `daily_gate.py:335` 의 업종 ETF 코드 허용)는 옛 스냅샷일 때만 켠다(R12)** — 2판 세션에서 「1306」「1617」 은 창작 수치다.

## 4. 코드가 만드는 문장과 표

작성자 본문에는 자리표시자만 둔다(표의 `<!--T:…-->` 와 같은 방식). 조립이 `facts` 로 문장을 만들어 `<p data-gen="이름">…</p>` 로 넣는다. 문구 틀은 `daily_render` 의 상수다.

| 자리표시자 | 절 | `current` 일 때 | 아닐 때 |
|---|---|---|---|
| `<!--G:topix-->` | 주식 | 문장 ① TOPIX: 「TOPIX는 3,824.00으로 전 거래일보다 0.42% 내렸다.」(0.00% 는 「…전 거래일과 같았다.」) 문장 ② 닛케이와의 방향 — **TOPIX 와 닛케이 등락률이 둘 다 있을 때만**: 부호가 다르면 「닛케이 225는 0.28% 올라 두 지수의 방향이 엇갈렸다.」, 같으면 「닛케이 225도 1.42% 내려 두 지수가 같은 방향으로 움직였다.」, 한쪽이 0.00% 면 방향 판단 없이 「닛케이 225는 0.28% 올랐다.」. 닛케이 등락률이 없으면(직전 CSV 행 결측 — `complete` 는 참, 8회차 #7) ② 를 뺀다 | TOPIX 가 `invalid`: 「TOPIX 종가를 확인하지 못해 싣지 않는다.」 — ② 도 없고 엇갈림 판단도 하지 않는다 |
| `<!--G:sectors-->` | 주식 | 문장 ① breadth: 「TOPIX-17 업종지수는 17개 업종 중 3개가 올랐고 14개가 내렸다(보합 0개).」 문장 ② 양 끝: 「가장 많이 오른 업종은 전기·정밀(+1.12%), 가장 많이 내린 업종은 소매(−1.55%)다.」 — 같은 값이 여럿이면 표 순서대로 **전부**(「A·B(+1.12%)」). 오른 업종이 0 이면 오른 쪽 구절을, 내린 업종이 0 이면 내린 쪽 구절을 뺀다. 등락률은 `facts` 의 소수 둘째 값 그대로 | 업종 블록이 `invalid`: 「업종별 지수를 확인하지 못해 싣지 않는다.」 |
| `<!--G:curve-->` | 채권 | 구간마다 한 문장: 「2~10년 금리 스프레드는 100.9bp로 전 거래일 대비 0.1bp 축소됐다. 10~30년 금리 스프레드는 118.6bp로 전 거래일 대비 2.5bp 확대됐다.」(변화 0.0 은 「전 거래일과 같았다」) | `stale`: 「JGB 는 11월 17일 기준 값이라 당일 스프레드 변화를 싣지 않는다.」 / 구간 `invalid`: 그 구간만 「…스프레드를 확인하지 못했다.」 |

- 표: 지수 표의 TOPIX 행(무효면 「—」), 업종 표 17행(무효면 표 없음), JGB 표에 스프레드 두 행(수준·변화를 **크기와 상관없이 그대로** — −0.1bp 도 −0.1bp). `stale` 이면 스프레드 행의 변화 칸은 「—」.
- **방향과 보합은 반올림한 등락률이 아니라 검증된 값의 차로 정한다**(13회차 — 3,840.02 → 3,840.01 은 −0.00% 로 표시되지만 내린 것이다. 표시값으로 판정하면 「같았다」 가 되고 닛케이와의 방향 비교도 빠진다): TOPIX·업종은 `종가 − 분모`, 닛케이는 `value − denom.value`, 스프레드는 반올림 전 변화의 부호. **차가 정확히 0 일 때만** 「전 거래일과 같았다」·보합이다. 업종 breadth 의 상승·하락·보합 집계와 두 지수의 「엇갈렸다/같은 방향」 판단도 이 부호로 한다. 차가 0 이 아닌데 표시가 0.00%(0.0bp)로 반올림되면 숫자 자리에 「0.01% 미만」(「0.1bp 미만」)을 쓴다 — 「TOPIX는 3,840.01로 전 거래일보다 0.01% 미만 내렸다.」
- 방향 낱말은 그 부호로만 정한다(확대/축소, 올랐다/내렸다). 「가팔라졌다」「평탄해졌다」 는 코드도 쓰지 않는다 — 그래서 9판의 0.5bp 편집 기준이 필요 없다.
- **이 문장들이 그날의 핵심 사실을 빠짐없이 담아야 한다** — 작성자는 TOPIX·업종지수 이름을 쓸 수 없으므로(§5) 두 지수의 엇갈림, 오른 업종 수, 양 끝 업종은 여기 말고 나올 자리가 없다. 작성자는 바로 뒤에서 이름 없이 해석한다(지시문 예: 「반등이 넓지 않았다」「대형 수출주에만 매수가 몰렸다」).
- 자리표시자 셋은 2판 스냅샷 세션의 필수 자리다(각 1번, 정해진 절 안). **넣는 자리를 조립기가 통제한다**(11회차 (b)2 — `<div hidden><!--G:topix--></div>` 는 개수·절·바이트 대조를 다 통과하면서 독자에게 안 보인다): 2판 세션에서 `<!--G:…-->`·`<!--T:…-->` 자리표시자는 그 절 `<section>` 의 **바로 아래 자식**이어야 하고(다른 원소 안이면 조립 거부), 절 여는 태그는 정해진 꼴 `<section class="card" data-section="이름">` 그대로여야 하며, 작성자 본문에 `hidden`·`style=`·`<style`·`<script` 가 있으면 조립이 거부한다. **본문의 맨 바깥에는 `<section>` 만 올 수 있다**(12회차 — 절 전체를 닫힌 `<details>` 로 감싸면 부모 검사가 그대로 통과했다): 2판 세션의 작성자 본문은 공백·주석을 빼면 머리 카드와 절 `<section>` 들의 나열이어야 하고, 무엇이든 절을 감싸는 원소가 있으면 조립이 거부한다. 그래서 생성 요소의 조상은 그 절 하나뿐이다. 게이트도 조립본에서 `data-gen` 요소와 코드 표의 부모가 그 꼴의 `<section>` 인지 다시 본다(조립기·조판이 붙이는 `id="read-N"` 은 허용 — 초안의 태그 제약은 그대로).

## 5. 게이트 — 작성자가 쓸 수 없는 것 (최소 규칙)

2판 스냅샷 세션에만 건다. 옛 발행본 16개는 지금 경로 그대로 다시 조립·검사된다(변경 전 출력과 바이트 동일 시험).

1. **생성 문장·표 대조**: `data-gen` 요소는 종류마다 정확히 1개, 정해진 절 안, 내용이 `render(facts)` 출력과 **바이트로 같아야** 한다. **코드 표도 같다**(8회차 #3 — 문장은 그대로 두고 표의 +2.5bp 만 −2.5bp 로 바꾼 글이 통과했다): 2판 세션의 표·캡션 조각(`render_tables(snap)` 의 지수·업종·JGB·엔·매크로·일정)은 각각 정확히 한 번, 렌더 출력과 바이트로 같아야 한다. 작성자 본문에 `data-gen` 속성이 있으면 조립이 거부한다. 생성 요소는 수치 검사에서 빼고 작성자 산문만 아래 규칙을 받는다.
   - **바이트 대조를 통과한 생성 요소·코드 표는 다섯 게이트 모두에서 코드 출력으로 다룬다**(16회차 — 견해 파일의 요약이 「TOPIX는 3,824.00으로 … 0.42% 하락했다」 면 필수 생성 문장이 현행 견해 겹침 검사(절이 없어도 절 밖 문장을 요약과 견준다)에 0.90 으로 걸려, 작성자가 고칠 수 없는 문장 때문에 정상 브리프가 멈춘다). 작성자 글을 겨냥한 검사 — 견해 요약 겹침(`telegram_gate`), 문체(`check_style`), 읽기 쉬움(`check_readability`), 뉴스 게이트의 절 밖 문장 검사, 창작 수치·금지 글자 — 는 이 요소들을 건너뛴다. **같은 문장을 작성자가 산문에 쓰면 그대로 걸린다**(대조를 통과한 그 요소만 면제다).
   - **조판은 생성 요소를 건드리지 않는다**: `apply_readability` 가 게이트 앞에서 글을 고쳐 쓰므로, `data-gen` 요소와 코드 표는 조판이 건너뛰게 하고(조판 전후 그 요소의 바이트가 같다는 시험) 바이트 대조는 조판 뒤의 조립본에 한다.
2. **작성자 산문**(`data-gen`·코드 표·**코드가 펼친 기사 블록(`<div class="news-item" data-news="…">`)**·유효한 견해 절을 뺀 보이는 글 전부 — `<p>`·제목·`<h2>`·`<li>`·작성자 캡션·`<title>`·`meta description`. **뉴스 절 안이라도 기사 블록 밖에 작성자가 쓴 글은 여기에 든다**(14회차 — 뉴스 절을 통째로 빼면 그 절에 쓴 `<p>TOPIX는 9,999.99로 마감했다.</p>` 가 일간 게이트와 뉴스 게이트를 둘 다 지나갔다. 2판 세션에서는 그 글에 아래 금지 글자와 3번, 기존 창작 수치 검사를 건다. 견해 절은 지금처럼 `telegram_gate` 가 요약과 대조한다. **기사 블록에서 빼는 것은 수집 요약 `summary_ko` 를 코드가 그대로 찍은 글자와 코드가 만든 출처 줄뿐이다**(15회차 — 블록 안에도 작성자가 쓰는 자리가 둘 있다: `<!--NEWS:guid|한국어 제목|연결 문장-->` 의 **제목**과 **연결 문장**. 제목만 `TOPIX는 9,999.99로 마감했다` 로 바꾼 글이 두 게이트를 지나갔다). 제목·연결 문장·손으로 쓴 기사 블록은 작성자 글이다: 숫자는 **그 기사**의 수집 필드(`title`·`summary_ko`)에 있는 것만, 지수 금지 글자(`TOPIX|토픽스|업종지수`)는 그 기사의 수집 필드에 같은 말(`TOPIX`·`トピックス`·`東証株価指数`·`업종지수`·`業種別`)이 있을 때만 쓸 수 있고, 커브·업종 개수·일정 부재 글자와 3번은 다른 산문과 똑같이 막는다)에서 막는 글자:
   - 지수: `TOPIX|토픽스|업종지수`. (TOPIX 에 대한 사실은 생성 문장이 말한다. 작성자는 그 문장 뒤에 이름 없이 해석한다.)
   - 커브: ⓐ 어디서든 `곡선|커브|기울기|장단기|스티프|플래트|steepen|flatten` ⓑ `금리|국채|JGB|수익률|년물` 이 든 문장에서 `가팔라|가파르|가파른|평탄|플랫|스프레드` ⓒ `금리차|격차` 가 `\d+\s*년` 또는 `\d+s\d+s` 와 한 문장에 있는 경우. 「미일 금리차」「주가가 가파르게 올랐다」「플랫폼」 은 그대로 쓸 수 있다.
   - 업종 개수: 「업종」 과 `\d+\s*개` 가 한 문장에 있는 경우.
   - 일정 부재: `없다|없었|없는|없어|없고|없으|부재` 와 `지표|발표|일정|통계` 가 한 문장에 있는 경우(§7).
3. **참조**: `data-ref` 경로가 `facts`·`curve`·`denom` 을 가리키면 차단(작성자가 새 데이터 숫자를 인용할 길이 없다). `facts` 의 값은 작성자 산문의 허용 수치 집합에 넣지 않는다.
4. 기존 검사(닛케이·JGB 수준·콜·엔의 `data-ref`, 창작 수치, 컨센서스, 「오늘」+콜·JGB, 절 순서 등)는 그대로.
- 이 규칙들은 글자 목록이라 동의어로 샐 수 있다(「수익률선이 섰다」). 다만 새는 것은 **숫자 없는 정성 서술**뿐이다 — 새 데이터의 숫자는 3번으로 길이 없고, 사실 문장은 바로 옆에 코드가 쓴 것이 있다. 정성 서술의 사실 검증은 지금도 닛케이·엔에 없는 기존 한계다.

## 6. 실행 격리 (A 에서 해결)

**현행 실측**: 초안·조립본은 레포 루트의 `jpd_<S>.*` 에 놓이고, 게이트 결과는 어디에도 남지 않으며, 발행 커밋은 `git add japan/daily japan/data/daily japan/data/history japan/daily.json sitemap.xml …` 로 **디렉터리를 통째로** 올린다. 실패한 실행이 남긴 파일이 다음 실행의 커밋에 실릴 수 있다.

1. **`run_id`**: STEP 0 에서 잠금을 얻은 직후 `jpd-<S>-<UTC 초>-<난수>` 를 정해 끝까지 쓴다.
2. **실행 폴더**: `_workspace/jpd/<run_id>/`(`/_workspace/` 는 이미 `.gitignore`). 본문·meta·조립본·게이트 결과가 전부 여기에만 놓인다. 다른 `run_id` 폴더는 읽지 않는다.
3. **시작 가드 — `HEAD` 가 `origin/main` 과 같은 커밋일 때만 시작한다**(8회차 #6, 9회차): 잠금 직후 `python3 scripts/ci/jpd_clean_start.py --key "$KEY" --session "$S"`. `git fetch origin main` 뒤 **가장 먼저 작업 폴더 전체를 본다**(10회차 #2): 발행 산출물 경로(아래) **밖에** 추적 파일 수정이나 미추적 파일(`.gitignore` 제외)이 하나라도 있으면 — `HEAD` 가 같든 뒤처졌든 — 아무것도 건드리지 않고 exit 3. 그다음 `git rev-parse HEAD == origin/main` 이고 발행 산출물 경로에도 변경이 없으면 0. `HEAD` 가 뒤처지기만 했고(앞선 커밋 0) 변경이 없으면 `git merge --ff-only origin/main` 으로 맞춘 뒤 0. 그 밖의 잔재는 **아래를 전부 확인했을 때만** 되돌리고, 하나라도 아니면 **아무것도 건드리지 않고 exit 3(실행 거부 + 경보)**:
   - 발행 산출물 경로 = `japan/daily/<S>.html` · `japan/data/daily/<S>.json` · `japan/data/daily/runs/<S>.json` · `japan/data/telegram/published/<S>.json` · `japan/data/history/jp_daily.jsonl` · `japan/daily.json` · `sitemap.xml`. **이 일곱뿐이다** — 수집 후보(`candidate/`)·BOJ 캐시·뉴스·견해 수집 파일은 들어가지 않는다(9회차: 폴더 단위로 잡으면 수집기 파일의 로컬 변경까지 지워진다).
   - ⓐ 이 사본이 이번 세션의 잠금을 쥐고 있다 — `.git/run_lock_<KEY>` 가 있고 그 SHA 가 원격 잠금 ref 와 같다(실측: `run_lock.sh` 가 잡은 SHA 를 이 파일에 적는다).
   - ⓑ 앞선 로컬 커밋이 **전부** 제목 `Add JP daily [` 로 시작하고 위 경로만 건드린다.
   - ⓒ 작업 폴더의 변경·미추적 파일(`.gitignore` 제외)이 **전부** 위 경로다.
   - 되돌리기 = `git reset --hard origin/main` + 위 경로 중 미추적 파일만 삭제(`git clean` 을 폴더에 쓰지 않는다). ⓑⓒ 덕에 지워질 수 있는 것은 실패한 발행의 산출물뿐이고, 사람이 쓰는 폴더는 잠금 파일이 없어(ⓐ) 거부된다. 환경 변수 표지는 클라우드 루틴 안의 값을 실측하지 못해 쓰지 않는다. 실측: 일본 일간은 클라우드 루틴으로 레포를 새로 받아 돌고, `scripts/runner_launch.py` 는 맥의 다른 러너 전용이다.
4. **입력을 커밋에서 한 번 고정한다**(8회차 #4, 10회차 #2): 작성자를 부르기 전에 수집 후보·뉴스 파일·견해 파일을 **`git show HEAD:<경로>` 로 꺼내** 실행 폴더의 `D/root/` 아래 같은 상대 경로에 쓴다 — 작업 폴더의 파일이 아니라 `HEAD`(= 그 시점의 `origin/main`, STEP 1 의 재수집·pull 뒤)에 들어 있는 바이트다. `HEAD` 에 없는 파일은 「없음」 이 그 실행의 상태다. 로컬에서 고쳐진 후보는 입력이 될 수 없다. `diag`·조립·다섯 게이트는 전부 `--root D/root`(뉴스 게이트는 `--datadir D/root/japan/data`)로 이 사본만 읽는다. STEP 1 의 「재수집을 건너뛰는 조건」 에 `schema == 2` 를 더한다(R7).
4-1. **검증 결과**: 새 래퍼 `scripts/jp_daily_gates.py --run-dir D --session S` 가 조판(`apply_readability`)까지 끝난 조립본으로 다섯 게이트를 차례로 돌리고, **전부 통과했을 때만** `D/gates.json` 을 한 번에 쓴다(임시 파일 → rename): `{run_id, session, html_sha256, snapshot_sha256, news_sha256|null, telegram_sha256|null, title, summary, gates: [{name, exit}], verdict: 'pass', finished_at}`. **`telegram_sha256` 은 게이트가 실제로 채택한 견해 바이트에만 붙는다**(10회차 #3): 파일이 있어도 `usable: true` 가 아니거나 형식이 달라 「없는 것」 으로 본 날은 `null` 이다 — 그날 발행기는 고정 파일을 만들지 않고 `verify-head` 도 「고정 파일 없음」 을 기대한다. 해시는 게이트를 돌리기 **전에** 재고, 다 돈 뒤 다시 재서 같을 때만 쓴다. `null` 은 「파일 없음」 이라는 상태이고 발행기도 같은 상태를 요구한다(뉴스 수집이 실패한 날도 지금처럼 발행된다, 8회차 #7). 하나라도 실패하면 파일을 만들지 않고, 있던 것은 지운다.
5. **발행기는 완료된 검증에만 묶인다**: `publish_japan_daily.py --run-dir D --run-id R` 이 아무것도 쓰기 전에 본다 — `gates.json` 이 있고 `verdict == 'pass'`, 그 `run_id == R == 폴더 이름`, `D` 의 조립본과 `D/root` 의 입력 사본 해시가 기록과 같다. 하나라도 어긋나면 exit 4, 아무것도 쓰지 않는다. 통과하면 **해시를 확인한 그 바이트를** 레포로 옮긴다(글 = `D` 의 조립본, 발행 스냅샷 = `D/root` 의 후보 + `published`). **제목·요약 인자를 없앤다**(8회차 #5 — `--headline` 으로 검증 밖의 문장을 목록에 실을 수 있었다): `japan/daily.json` 항목은 검증된 조립본의 `<title>`·`meta description`(= `gates.json` 의 `title`·`summary`)에서만 만든다. rebase 충돌 복구(`update_archives.py`)도 `runs/<S>.json` 의 그 값을 읽고, push 직전에 `japan/daily.json` 의 이 세션 항목이 그 값과 같은지 본다.
6. **발행 기록**: 발행기가 `japan/data/daily/runs/<S>.json`(= `gates.json` + `published_at`)을 쓰고, 이번 발행이 만든·바꾼 경로를 `D/manifest.txt` 에 적는다: 글, 발행 스냅샷, `runs/<S>.json`, 이력, `japan/daily.json`, `sitemap.xml`, (있으면) 견해 고정 파일.
   **쓰는 순서(codex 구현 2회차 — 발행 도중 중단)**: ① `D/publish.json` 에 바꿀 경로와 그 바이트의 해시·목록 항목·이력 행을 **쓰기 전에** 남긴다 ② 경로마다 `D` 안 임시 파일 → `os.replace` 로 통째로 바꾼다 ③ `D/manifest.txt` 를 마지막에 쓴다(완료 표식 — 없으면 `check-staged`·`verify-head` 는 4). 어디서 죽어도 산출물 경로는 origin 판이거나 기록의 바이트라 §6-3 시작 가드가 되돌린다. 손으로 고친 바이트·삭제·다른 세션 기록은 여전히 설명되지 않는다. 실행 폴더가 저장소와 다른 장치면 아무것도 쓰지 않고 4.
   **뉴스 블록의 수치(codex 구현 1회 #7 → 2회)**: 제목·연결 문장의 수치는 크기·단위와 무관하게 **그 기사**의 `title`·`summary_ko` 에 있어야 한다(12 이하 정수 면제 없음, 다른 기사의 수도 안 됨). 제목의 `N月`·`N日` 은 글의 「N월」「N일」 만 허락한다. 발행본 17편 115조각에 걸어 보니 새로 막히는 것은 1건(「続伸」→「2거래일 연속」)이다.
7. **명시 경로만 스테이징**: 오케스트레이터는 `git add -- $(cat D/manifest.txt)` 만 쓴다. 디렉터리 단위 `git add` 를 없앤다. 커밋 직전 `git diff --cached --name-only` 가 manifest 와 **정확히 같아야** 하고, 다르면 커밋하지 않고 3 의 되돌리기를 한 뒤 경보.
7-1. **push 직전, 최종 커밋 전체를 검증 기록과 대조한다**(9회차 #1, 11회차 (b)1 — 발행기가 옮긴 뒤 스테이징 전에 글의 생성 문장만 바꿔도 경로 집합은 같다): 발행기는 옮긴 것의 해시를 `D/publish.json` 에 남긴다(글 `html_sha256`, `published` 가 들어간 **최종 발행 스냅샷 바이트**의 `published_snapshot_sha256`, `runs/<S>.json` 의 해시, 견해 고정 파일 해시|없음). 첫 push 든 rebase 뒤든 push 직전에 `publish_japan_daily.py verify-head --run-dir D` 가 **`HEAD` 커밋에서** 꺼낸 글·발행 스냅샷·`runs/<S>.json`·견해 고정 파일·이 세션 뉴스 파일(없으면 「없음」)의 해시와 `japan/daily.json` 의 이 세션 항목을 그 기록과 견준다. 하나라도 다르면 **push 하지 않고** 8 의 되돌리기 + 잠금 해제로 끝낸다. 재시도 회차가 새 `run_id` 로 다시 쓴다. 최종 회차였으면 미발행 경보.
8. **중단 경로**: 발행기 뒤 어느 단계에서든 push 없이 끝날 때는(커밋을 만든 뒤 push 가 끝내 실패한 경우 포함) 3 의 `reset --hard origin/main` 을 하고 끝낸다. 실행 폴더는 남겨도 된다 — 다음 실행은 새 `run_id` 라 읽지 않는다.
- 수집 워크플로의 `git add japan/data/daily …` 는 Actions 의 새 checkout 에서 후보·뉴스만 올리므로 그대로 둔다. `runs/` 와 발행 스냅샷은 발행 단계만 쓴다.
- 전환: 미발행 후보가 2판이 아니면 `diag` exit 1(다시 수집), 발행기 exit 2.

## 7. 일정표 (줄인 판)

- `calendar_daily.json` 에 계열별 확인 창 `coverage: [{id, name_ko, cadence, source, from, through, checked_at}]` 과 행마다 `cov: <id>`(기존 `series` 는 BOJ 조회 열쇠라 건드리지 않는다). 필수 계열 16개(BOJ 정책·CPI 전국/도쿄·GDP·CGPI·SPPI·통화량·본원통화·임금·단칸 + 새로 무역통계·광공업생산·노동력·가계·상업동태·기계수주). 확인 못 한 계열은 항목을 만들지 않는다. **검증(R6)**: `cov` 가 `coverage` 의 id 이고, `from ≤ through`·`source` 있음, **행의 날짜가 그 계열 창 안**이어야 한다. 어긋난 계열은 「미확인」 으로 친다(파일 전체를 버리지 않는다).
- 수집 때 스냅샷에 `calendar.coverage = {today_missing, upcoming_missing}` 을 고정한다. `today_missing` = 대상일을 창이 덮지 못하는 필수 계열, `upcoming_missing` = **대상일부터 대상일+14일까지 전체 구간**을 창이 덮지 못하는 필수 계열(R10 — 끝 날 하루만 덮는 것으로 읽히지 않게). `monthly` 계열은 창에 완전히 드는 달마다 **`release` 행**(회의 행은 세지 않는다)이 1개 이상이어야 덮은 것으로 친다. `checked_at` 이 유효한 날짜가 아닌 계열은 미확인이다(R10).
- **부재는 코드 캡션만 말한다**: 그날 행(발표·회의 모두)이 0 이고 `today_missing` 이 비었을 때만 「확인해 둔 발표 일정표(…범위…)에 오늘 잡힌 일본 지표가 없다.」. 미확인 계열이 있으면 「발표 일정표 미확인 계열: X·Y.」, 회의 행만 있으면 「오늘 일정표에는 회의 일정만 있다: …」. 앞날 캡션도 같은 방식. 작성자는 부재를 쓰지 않는다(§5-2). 옛 스냅샷은 옛 캡션.
- 알림: `jp_calendar_notes` 가 필수 계열마다 확인 창이 `[오늘, 오늘+21일]` 을 덮는지 보고 덮지 못하는 계열을 이름으로 알린다. **수집기와 같은 판정 함수를 쓴다(R14)** — 창의 기간뿐 아니라 위 검증(`cov`·`checked_at`·창 안의 행·monthly 의 `release` 행)에 실패한 계열도 알림에 이름이 나온다.
- 한계: 발표 연기·취소는 사람이 고칠 때까지 모른다.

## 10. 기존 한계·미해결 (A 가 풀지 않는다)
- **우연히 같은 숫자**: 작성자 산문의 숫자는 「스냅샷 어딘가에 있는가」 로만 본다(닛케이·엔·금리 수준·개별주·매크로 공통, 전일 종가 == 당일 종가인 날 포함). 게이트 통과는 「날짜 검증 완료」 가 아니다. 10판은 새 데이터(TOPIX·업종·스프레드)를 이 구조 밖에 둔다 — 숫자가 작성자 허용 집합에 없고 문장은 코드가 쓴다. 후속 작업(별도): 기존 필드도 `facts` 로 옮기고 문장이 가리키는 지표·관측일에 맞는 값인지 확인한다.
- **정성 서술**: 「넓은 시장은 약했다」「은행이 부진했다」 처럼 숫자 없는 방향 서술은 검증하지 않는다(지금도 같다).

- 백필(시작 시 1회, 이후 매 실행 빈 날 메움): TOPIX 는 네이버 4,000행 이력, 닛케이는 일경 CSV, 업종은 JPX `price3.{1..5}` 5일분만(그 전 업종 이력은 없다 — ETF 이력과 잇지 않는다).
- **우선 규칙**(검토 #3): 발행된 세션은 발행 스냅샷 값이 이긴다. 미발행 세션은 검증된 원천값. 백필 원천과 발행값이 다르면 `notes` 에 남기고 발행값을 쓴다(교정은 기존 정정 경로로만). 각 계산 결과에 양 끝 `{date, value, source}` 를 고정해 스냅샷에 남긴다.
- **거래일**(검토 #4): 기존 `holidays` 로 거래일 열을 만들고, 휴일 파일(`data/market_holidays.json` `jp`: 2026-01-01 ~ `valid_through` 2027-12-31, 평일 휴장 36일)이 그 구간을 덮지 않으면(`valid_through` < session 또는 창의 시작 < 첫 해의 1월 1일) 그 지표 결측. 원장에 필요한 날짜가 없거나 중복이면 그 지표 결측. N 거래일 전 = 거래일 열에서 정확히 N 칸 앞(유효 행 N 개 세기 금지).

### B1. 지표

| N일 수익률 (N=5,20,60) | close[t]/close[t−N] − 1, %, 소수 둘째 | 두 끝 날짜 행 | TOPIX·닛케이·업종 17 |
| TOPIX 대비 상대성과 | 업종 N일 수익률 − TOPIX N일 수익률, %p (단순 차, 같은 JPX 원천) | 두 끝 모두 업종·TOPIX | 업종 17 |

- JGB(검토 #5): 원장은 자체 발행 이력만(현재 16행 → 5일은 지금, 20일은 쌓인 뒤). 끝의 `source` 가 다르거나 MOF 폴백 행(관측일 = prev_session)이 끼면 결측. 본문은 「(11월 11일 대비)」 처럼 기준 날짜를 붙인다(게이트 기존 `_period_of` 규칙을 B 필드에 확장). 네이버 지표물 교체는 감지할 수단이 없다 — 같은 날 MOF 값과 15bp 넘게 다르면 이미 막히는 기존 검사를 B 에도 적용하고, 남는 위험은 spec 에 적는다.
- 업종 20·60일은 JPX 5일 백필 뒤 쌓여야 생긴다(20일 ≈ 시작 후 15거래일, 60일 ≈ 55거래일). 그 전 칸은 「—」.
- 「평소의 약 N배」 로만 쓴다. 확률·유의·이상치·「통계적」 어휘 금지(게이트).

### B2. 인용 계약(검토 #8)
- B 숫자는 전부 `<span data-ref="b.…">` 로 묶는다. 게이트: B 필드가 결측(None)인데 그 data-ref 를 쓰면 차단. `data-ref` 없이 「(\d+(\.\d)?)\s*배」 또는 「5거래일|20거래일|60거래일|한 달|1주|석 달」+ 수치가 든 절 → 차단(기간 수익률을 묶지 않고 쓰는 것). 수치 없는 정성 표현(「평소보다 컸다」)은 막지 않는다 — 문체 규칙을 더하지 않는 원칙. 대신 그 문단에 배수 data-ref 가 없으면 digest 경고.

## C. 판단 기록·복기 (B 확인 뒤)

KR 판단 원장·US 성적표의 원리. **매일 판단을 강제하지 않는다.**

### C1. 원장 = 이벤트 append-only (`japan/data/judgments.jsonl`)
이벤트 종류(검토 #14): `open`, `observe`, `close`, `withdraw`, `correct`. 공통 `{event_id, judgment_id, prev_event_id, kind, session, recorded_at, reason}`.
- `open`: `{thesis(≥20자), basis:[{ref, value, session}](당시 값 고정), metric, op, level, level_source, start:{session, value}, horizon_sessions, check_session(코드가 거래일 열로 계산), falsifier:{metric, op, level, level_source}}`.
- 목표·만기·반증을 바꾸려면 기존 판단을 `withdraw`(사유 필수)하고 새 `open`. 같은 judgment_id 의 `open` 은 하나뿐(시험).
- `correct`: 원천 정정으로 과거 값이 바뀐 경우만, 이전 값·새 값·근거 커밋.

### C2. 허용 지표와 판정식(검토 #12)
| metric | 값 | op |
|---|---|---|
| `topix_ret`, `nikkei_ret` | start.session 종가 → 관측 세션 종가 수익률(%, 소수 둘째) | `>`·`<` |
| `sector_rel:<key>` | 업종 수익률 − TOPIX 수익률(같은 구간, %p) | `>`·`<` |
| `topix_close`, `nikkei_close` | 종가 | `>`·`<` |
| `jgb_yield:<tenor>`, `curve:<s2s10|s10s30>` | 같은 원천 값(bp 차는 start 대비) | `>`·`<` |
- 비교는 엄격 부등호, 같으면 불충족. 반올림 후 비교.
- **level 의 출처**(임의 임계값 금지): `level_source` 는 ① `zero`(수익률·상대성과·bp 차의 0) ② `start`(시작 값) ③ 그날 `diag` 의 계산값 경로(예: `b.topix.high_20`, `b.topix.low_20` — 20·60일 고가·저가 종가, B 에 추가) 중 하나. 코드가 `level == resolve(level_source)` 를 검증하고, 아니면 등록 거부. 자유 숫자 불가.
- 등록 상한: 열린 판단 3개. 지표 계산이 안 되는 날(B 결측)의 등록은 거부.

### C3. 판정 순서(검토 #13)
매 세션 수집 뒤 코드가:
1. 관측 = **종가만**(장중 무시). 그날 해당 지표 결측이면 `observe` 에 `missing:true`.
2. 반증 먼저: 관측값이 falsifier 를 충족 → `close`(결과 `무효`).
3. check_session 이 아니면 `observe`(진행 값만, 판정 어휘 없음).
4. check_session: 반증 충족이면 `무효`(동시 충족도 `무효` 우선). 아니고, 기간 중 결측 세션이 하나라도 있으면 `판정 불가`(반증 여부를 모르므로). 아니면 목표 충족 `맞음` / 불충족 `틀림`.
- 결과 어휘는 넷뿐: `맞음`·`틀림`·`무효`·`판정 불가`.
- 성적(적중률)은 종결 20건 전에는 쓰지 않는다(게이트, US 와 같은 규율).

### C4. 발행 구조(검토 #15)
- 새 선택 절 `judgment`(「판단 기록」), 위치는 전략 코멘트 바로 뒤, 열린 판단이나 그날 종결이 있을 때만. 렌더러 `OPTIONAL` 에 넣고 절 순서 검사에 포함. 표는 코드가 원장에서 렌더(작성자가 숫자를 쓰지 않는다), 작성자는 판단 문단만.
- 어휘: 주간 신호 어휘 금지(`_SIGNALS`)는 그대로 — 판단 절은 「반증 조건」「기준」을 쓰고 「임계값」을 쓰지 않는다. 컨센서스·지수 기여 금지는 새 절에도 적용(통합 시험).
- 작성자가 새 판단을 낼 때는 별도 파일(`judgment_next.json`, KR `kr_stance_next.json` 와 같은 방식)로 내고, 오케스트레이터가 검증 뒤 원장에 `open` 을 덧붙인다.
