# 매일 검증 알림 (2026-11-08)

## 왜

면접 지적(사용자 전달): 「AI 리포트를 자동화하려면 내용·숫자가 맞는지 검증하는 장치가 있어야 하고, 본인이 그 검증이
무엇을 잡고 무엇을 못 잡는지 알아야 한다」. 사용자 지시: 검증 결과는 **발행본에 적지 않고** 매일 알림으로, 채널은 텔레그램.

## 무엇을 하나

Mac launchd(`com.fdo2a.verify-digest`, 매시 20분) → `runner_launch.py digest`(origin/main 사본) → `scripts/verify_digest.py`.
KST 9시 이후 그날 처음 한 번만 보낸다. AI 를 부르지 않는다.

**매일 90일 안의 공개판 글을 전부 다시 평가**하고, 글별 전달 기록(공개 blob + 보낸 문장)과 비교해 바뀐 글만 자세히 쓴다.
창·미해결·미전달을 따로 고르던 방식은 codex 구현 검토 1-4회차에서 가장자리마다 글이 조용히 빠졌다(밀린 글, 창 밖 수정,
창 밖 상태 변화, 첫 알림 전 미해결, 90일 경계, 삭제, 늦게 올라온 옛 글). 숫자 재검사는 (blob, 검사기 코드 해시) 캐시라
첫 실행 22초·이후 3초(실측).

| 줄 | 근거 | 하지 않는 것 |
|---|---|---|
| 숫자 | US 일간만 — 발행 커밋의 글 + 그 날 `market_data.json` 판으로 `check_numbers.py --json` 재실행. 다시 그린 글은 같은 날짜 수집판으로 대조하고 「추정」이라 적는다 | 발행 전 결과를 보여 주지 않는다(루틴 로그에만 있다). 「발행 뒤 재검사」라고 적는다 |
| codex 검토 | review_gate 분류(미검토·조판·판정 불가)·만료를 **공개판에만** 적용, 원장 `findings`, 초안 유무 | `findings` 를 정정 수로 읽지 않는다 — 원장의 채택 지적 수 |

머리 안내: 첫 알림, 지난번 실패, 최신 판을 못 받음, 공개판에서 사라진 글, 90일이 지나 추적을 멈춘 미해결·미전달 글,
90일보다 오래된 날짜의 새 글(검사 안 함). 합계는 「최근 7일」(오늘 포함 7개 날짜) 글만.
잘릴 때는 창 안 최신 글이 먼저 — 못 보낸 글은 기록하지 않아 다음 알림에 나온다.

## 2.5단계 — 맥은 제출만, 전송은 Cloudflare Worker (2026-11-10)

설계·계약 정본은 레포 밖(프로젝트 루트의 `design-2.5-github-cloudflare.md` v1-v11, `alerts-contract-2.5.md` §3·§4). 여기는 맥 쪽 요약만.

- **토큰 없음.** 직접 전송·대화 번호 설정(`--setup-chat`) 코드를 지웠다. 열쇠고리 service `fdo2a-alerts` 의 `digest_key`(제출 키)·
  `worker_url`(https 주소, 경로 없이)만 읽는다. 사람이 `security add-generic-password -U -s fdo2a-alerts -a digest_key -w` 로 직접 넣는다.
  키·본문·주소는 curl 설정 stdin 으로만 가고, 모양(키 32-128자, https 호스트)이 다르면 curl 을 부르지 않는다.
- **제출본을 먼저 고정.** `pending = {id, date, v, text, base, tries}` 를 저장한 뒤 `POST /digest`. 시도는 보내기 **전에** `noresp` 로
  적고 응답으로 덮어쓴다(빈 시도 목록을 「전부 거절」로 읽지 않게). 다시 낼 때는 그 본문 그대로. 응답 분류: 202 `accepted`,
  200 `dup`, 409 `conflict`, 400·401 `rejected`, 그 밖 전부(5xx·약속에 없는 코드·JSON 이 아닌 200) `server`, 무응답 `noresp`.
  기한 전에는 `/status` 에 그 id 가 보여도 같은 본문을 다시 낸다 — 200 이어야 내 본문이다(기록을 잃고 새로 만든 본문이면 409).
- **접수 ≠ 전송.** `due()` 는 `last_submitted_day`(접수). 접수되면 본문을 버리고 `unconfirmed` 에 기준(`base`)만 둔다. 매 tick
  `GET /status` 로 확인해 `sent` 인 요약의 기준을 **(날짜, 버전)이 더 클 때만** 적용하고 `last_sent` 에 Worker 의 `sent_at` 을
  그대로 적는다. 그 전까지 `lines` 는 전진하지 않는다 → 다음 요약이 같은 변화를 다시 담는다. `failed_permanent`·`held` 는
  기준 없이 내려놓고 다음 요약 머리에 「지난 알림 실패 — 전송 오류/전송 보류」.
- **기한.** 어제 치 `pending` 은 오늘 9시 전 tick 까지 같은 본문으로 다시 내고, 오늘 요약을 만드는 tick 에서 `/status?id=` 로 정리한다:
  사건이 있으면 접수로 기록(409 를 받았었다면 「접수됨 — 다른 본문이 먼저 접수돼 있었어요」, 기준 미적용), 없으면 모든 시도가
  400·401 일 때만 「어제 요약 접수 실패」, 그 밖은 「어제 요약 접수 여부 확인 불가」. 꼬리에 한 번 싣고 새 날짜 id 로 새로 만든다.
- **본문 대조(codex 구현 1회 #4).** `/status` 에 그 id 가 있다는 사실만으로 자기 본문이라 믿지 않는다. 기준은 사건이 `sent` 이고
  `hash` 가 맥이 고정한 본문의 sha256 과 같을 때만 적용한다. hash 가 다르면 409 와 같게 「접수됨 — 다른 본문이 먼저 접수돼
  있었어요」(기준 미적용), hash 가 없으면 적용하지 않고 「확인 불가」.
- **401 과 보관(codex 구현 1회 #2).** `/digest`·`/status` 의 401 은 제출 키 설정 오류다 — 세션 훅에 「요약 제출 키 오류 — Worker 가
  제출을 거부해요(키체인 digest_key 와 Worker Secret 확인)」, 다음 요약 머리에 한 번. 접수되지 못하고 기한이 지난 제출본은
  지우지 않고 기록 파일 옆 `verify_digest.expired.jsonl`(0600, 30일)에 본문·기준·시도째 남긴다. 다시 제출하지는 않는다(Worker 가
  받는 날짜가 지났다) — 기준이 적용되지 않았으니 다음 요약이 같은 변화를 다시 담는다.
- **기밀은 구조로.** 실패 사유는 종류만 저장·표시(`ERRORS`), 머리 안내는 정해진 문구만(`NOTE_PATTERNS`, 그 밖은 「기타 안내 n건」),
  초안은 「검토 진행 중」, 검사기 원문 줄·판정 불가 사유·발행 전 기록 예외 문장은 종류와 개수만. 정규식(`scrub`)은 보조 —
  걸린 줄은 「(내부 정보 — 생략)」, 그 글은 문장표에 적지 않고, 꼬리에 「n줄 생략 — 맥에서 확인」.
- **크기.** 글 3,900자·요청 16,000 B(UTF-8 그대로 잰다) 안. 넘으면 글을 더 미뤄 다시 만든다(`compose`).
- **꼬리.** 발행 알림 상태는 `origin/alerts-state:verify_publish.json`(GitHub 계산)을 읽는다 — 브랜치 없음 「GitHub 계산 기록이 아직
  없어요」, 못 읽음 「상태를 못 읽었어요」, 오래됨 판정은 `publish_watch.GITHUB_STALE`(9시간). Worker `/status.health` 는 이상할 때만 「전송기:」 한 줄(밀림·영구 실패·9시간 넘게 계산 기록 없음·조회 실패).
- **한 번 생기는 되풀이.** 문장이 바뀐 글은 첫 새 요약에 「바뀐 상태」로 다시 나온다: 숫자 경고·위반 원문 줄이 있던 US 일간
  (11/10 실측: 같은 글 180편에서 옛·새 문장이 다른 것 2편)과 초안이 나와 있던 대기 글(그날 맥의 전달 기록 175편 중 1편).
  숫자 재검사 캐시도 한 번 새로 계산한다.
- 남는 위험: 맥의 코드가 제출 키를 읽으면 거짓 요약을 낼 수 있다(토큰은 못 가져간다). `--force` 는 같은 날 수정본(v2…)을 낸다 —
  Worker 는 하루 수정본 2개까지 보내고 그 뒤는 `held`.

## 한계(알고 둔다)

- 3,900자를 넘는 안내(수백 편 대량 삭제 등)는 이름이 잘린 채 기록이 비워진다(codex 5회차 #5 기각 — 사람이 하는 일이라 그 자리에서 안다).
- 발행 전 결과가 아니라 발행 뒤 재검사다. 뜻·해석 오류, 원 데이터 자체의 오류는 이 알림 밖이다.
- Mac 이 꺼져 있으면 그날 알림이 없다(잠자기면 깨어날 때). 세션 시작 훅이 30시간 경과를 보인다.
- 접수 응답을 못 받은 요청이 뒤늦게 처리되면 「확인 불가」로 적은 어제 요약이 실제로는 갔을 수 있다 — 그래서 단정하지 않는다.
