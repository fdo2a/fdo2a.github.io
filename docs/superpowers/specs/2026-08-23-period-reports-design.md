# US·KR 브리프 — 주간·월간 정리 설계

작성일: 2026-08-23
대상: 신설 발행물 4종 (US 주간/월간 정리, KR 주간/월간 정리)
개정: 2026-08-24 — 사용자 지시로 성격 재정의(발행본 총정리), 코멘트 폐기, 네비 서브카테고리

## 문제

일간 브리프는 하루를 잘 설명하지만, **하루를 넘는 시계에서 무슨 일이 있었는지는 아무도
정리하지 않는다.** 독자는 5편을 각각 읽어 스스로 합산해야 하고, 한 달을 관통한 흐름은
어디에도 남지 않는다.

더 큰 구멍은 검증이다. 이 프로젝트는 「승계되는 판단」에 이미 크게 투자했다 —
`stance.json`이 7개 자산군의 포지션을 물려주고, `macro.json`이 레짐을 물려준다.
그런데 **그 판단이 맞았는지 되돌아보는 자리가 없다.** 게다가 두 파일 모두 매일
덮어쓰기라 과거 판단의 이력조차 보관되지 않는다.

## 이 리포트의 성격 (2026-08-24 사용자 지시로 재정의)

**주간·월간 정리는 「그 기간에 발행한 리포트들의 총정리」다.** 시장을 새로 취재하는 글이
아니라, 이미 나간 글들을 읽고 한 편으로 묶는 글이다. 금요일 리포트가 올라간 다음날,
지난 5일치 발행본을 놓고 그 주에 무슨 일이 있었는지 정리한다. 월간도 같은 성격으로
그 달 발행본 전체를 놓고 정리한다.

이 정의가 입력을 결정한다 — **주 소스는 원천 시세가 아니라 `posts/*.html`(KR은
`kr/posts/*.html`)이다.** 그 기간의 촉매·해석·판단은 일간이 이미 확정했으므로 웹을
다시 뒤지지 않고, 시세도 다시 받지 않는다.

**예외는 기간 합산치 하나다.** 「이번 주 S&P 500 +1.8%」 같은 값은 일간 5편의 등락률을
곱해야 나오고, 그건 작성 에이전트의 산술이라 발행 게이트가 막는다(수치 창작 금지).
그래서 기간 수익률표만 결정론적으로 계산된 집계 파일에서 채운다. 본문 서술은 발행본,
성과표는 집계 파일 — 두 소스가 하는 일이 갈린다.

## 목표

- 그 기간 발행본이 **한 편으로 묶일 것** — 5편을 각각 읽지 않아도 흐름이 보이게
- 과거 판단이 **정량으로 채점될 것** — 인상이 아니라 누적 적중률로
- 승계 책의 이력이 **append-only로 보관될 것** — 복기와 무관하게 있어야 할 자산
- 기간 합산 수치는 **결정론적으로 계산되어 작성 에이전트에게 완성된 상태로 전달**될 것
  (`macro_metrics.json`이 z를 계산해 넘기고 writer가 만지지 않는 것과 같은 규율)

**비목표**: 주간·월간을 위한 새 취재나 웹 리서치, KR 스탠스 책 도입(후속 과제),
수익률 백테스트, 주간 리포트의 에디터 노트 지원, 새 GitHub Actions 워크플로 신설
(기존 둘을 확장한다), **주간 코멘트 별도 발행물**(2026-08-24 사용자 지시로 폐기 —
섹션 구조가 일간·주간·월간 셋이라 들어갈 칸이 없다).

## 발행물 매트릭스

| 시점 | 발행물 | 경로 | 목록 |
|---|---|---|---|
| 토요일 | US 주간 정리 | `/weekly/YYYY-MM-DD.html` | `weekly.json` |
| 토요일 | KR 주간 정리 | `/kr/weekly/YYYY-MM-DD.html` | `kr/weekly.json` |
| 월 마지막 거래일 다음날 | US 월간 정리 | `/monthly/YYYY-MM.html` | `monthly.json` |
| 월 마지막 거래일 다음날 | KR 월간 정리 | `/kr/monthly/YYYY-MM.html` | `kr/monthly.json` |

주간 파일명은 **ISO 주 키**(`2026-W35`)다. 2026-08-30 구현 시점에 「커버 기간의 마지막
거래일」에서 바꿨다 — 집계 파일이 이미 주 키로 나뉘어 있어(`data/weekly/2026-W35.json`)
URL만 거래일로 두면 같은 것을 두 이름으로 부르게 되고, 그 주의 마지막 거래일이 휴장으로
움직일 때 URL이 따라 흔들린다. 월간은 원래대로 `YYYY-MM`이다. 경로가 달라
`/posts/2026-08-21.html`과 충돌하지 않는다.

## 네비게이션 (2026-08-24 사용자 지시)

상단 메뉴바의 「미국 시장」·「한국 시장」 **각각 아래에 일간·주간·월간 세부 카테고리**를
둔다. 발행물은 그 셋 중 하나에 들어간다. 「메모리 thesis」는 성격이 달라 서브카테고리
없이 그대로 둔다.

## 기간 경계

**주간** = ISO 주(월~일). 커버 종료일은 그 주의 마지막 거래일이며, 데이터가 판정한다 —
금요일이 휴장이면 목요일이다. 날짜 산술로 도출하지 않는다(2026-07-15 중복 생성 버그와
같은 부류의 실수).

**월간** = 그 달의 첫 거래일 ~ 마지막 거래일.

**휴장 달력을 두지 않는다.** 대신 수집기가 **기간 키로 파일을 나눠 쓴다**:

- `data/weekly/<YYYY>-W<ww>.json` — ISO 주 키
- `data/monthly/<YYYY-MM>.json` — 달 키

매 실행마다 `report_date`가 속한 주/달의 파일을 갱신한다. 주가 넘어가면 지난주 파일은
갱신을 멈추고 **그 자체로 확정본이 된다.** 별도의 「동결」 단계도, `month_end` 같은
플래그도 필요 없다. 발행 여부는 다음과 같이 판정한다:

- 주간: 토요일 트리거가 최신 `report_date`의 ISO 주 파일을 발행한다(그 주는 이미 끝났다)
- 월간: 최신 `report_date`의 달이 M+1인데 `data/monthly/<M>.json`이 있고 아직
  `/monthly/<M>.html`이 없으면 M을 발행한다

같은 기간을 다시 돌리면 **덮어쓴다**(추가 생성이 아니라 교체). 목록 JSON과 sitemap도
기간 키로 upsert하므로 재실행이 중복 항목을 만들지 않는다.

## 데이터 계약

### 기간 집계 — `data/weekly/<key>.json`, `data/monthly/<key>.json`

```
{
  "span": "weekly" | "monthly",
  "key": "2026-W34" | "2026-08",
  "start_date": "2026-08-17",      // 그 기간 첫 거래일
  "end_date": "2026-08-21",        // 그 기간 마지막 거래일 (= 커버 종료일)
  "sessions": 5,                    // 포함된 거래일 수
  "complete": true, "missing": [],
  "indices":     { "S&P 500": {"start": .., "end": .., "pct": ..}, ... },   // 6종
  "sectors":     { "Technology": {"pct": .., "rank": 1}, ... },             // 11종
  "yields":      { "10Y": {"start": .., "end": .., "chg_bp": ..}, ... },   // start/end 는 퍼센트 레벨(4.20), 변화만 bp
  "curve":       { "spread_2s10s_bp": {"start": .., "end": .., "chg": ..}, "spread_5s30s_bp": {...} },
  "fx":          { "DXY": {...}, "USD/KRW": {...}, ... },
  "commodities": { "WTI": {...}, ... },
  "memory":      { "<ticker>": {...}, ..., "basket_pct": .., "basket_excess_pct": .. },
  "ai_infra":    { ...,               "basket_pct": .., "basket_excess_pct": .. },
  "daily":       [ {"date": "2026-08-17", "spx_pct": .., "headline": "..."}, ... ]
}
```

`basket_excess_pct` = 바스켓 수익률 − S&P 500 수익률. 메모리·AI 인프라 스탠스가
**주식 대비 상대비중**이므로 채점에는 이 값을 쓴다.

`daily[].headline`은 그 주 일간 발행본 `posts.json`에서 회수한다. **웹 재리서치 금지** —
그 주의 촉매는 이미 일간에서 확정했다.

KR판 `kr/data/weekly/<key>.json`·`kr/data/monthly/<key>.json`:

```
{ "span", "key", "start_date", "end_date", "sessions", "complete", "missing",
  "indices":   { "KOSPI": {"start","end","pct"}, "KOSDAQ": {...} },
  "flows":     { "KOSPI": {"foreign": .., "institution": .., "individual": ..}, "KOSDAQ": {...} },
  "flows_sessions": 5, "flows_note": "확정치만 합산",
  "industry":  { "<업종>": {"pct": .., "rank": ..} },
  "top_value": [ {"name": .., "value_krw": ..} ],   // 기간 합산, ETF 정규화 후
  "daily":     [ {"date", "kospi_pct", "kosdaq_pct", "headline"} ] }
```

**수급은 확정치만 합산한다.** `flows_provisional`이 참인 날은 제외하고 `flows_sessions`에
실제 합산 일수를 적는다. 잠정치를 섞어 누적하면 수치가 나중에 조용히 틀려진다
(2026-08-05 실측: 장중 +15,116 vs 확정 +14,464).

### 승계 책 이력 — `data/history/stance.jsonl`, `data/history/macro.jsonl`

한 줄 = 하루. 수집기가 커밋된 `data/stance.json`·`macro.json`을 읽어 append하며,
`report_date`가 이미 있으면 건너뛴다(멱등). 스키마는 원본을 그대로 담되 용량을 위해
`thesis`는 보존하고 `triggers`는 발동 여부 판정에 필요한 필드만 남긴다.

기존 이력은 `scripts/backfill_history.py`가 git 히스토리에서 **1회 백필**한다
(`git log --format=%H -- data/stance.json` → 각 커밋의 blob을 읽어 append).

### 스코어카드 — `data/scorecard.json` + `data/history/scorecard.jsonl`

`scripts/us/scorecard.py`가 계산한다. **작성 에이전트는 이 숫자를 만들지도 고치지도
않는다.**

## 복기 스코어카드 (US)

채점 대상은 **스탠스 7개 자산군의 등급 부호**다. 등급이 곧 방향 베팅이다.

| 키 | 실현치 | 부호 규칙 |
|---|---|---|
| `equities` | S&P 500 기간 수익률 | 그대로 |
| `bonds` | 10Y 금리 변화(bp) | **부호 반대** (롱 듀레이션 = 금리 하락 베팅) |
| `fx` | DXY 기간 수익률 | 그대로 (등급 + = 달러 롱) |
| `energy` | WTI 기간 수익률 | 그대로 |
| `metals` | 금 기간 수익률 | 그대로 |
| `memory` | 메모리 바스켓 **초과수익** | 그대로 |
| `ai_infra` | AI 인프라 바스켓 **초과수익** | 그대로 |

**판정 규칙**

- 기간 시작 시점의 등급(= 그 기간 첫 거래일 아침의 책)으로 채점한다. 기간 중 등급이
  바뀌면 구간을 쪼개 각 구간의 실현치로 채점하고 |등급| 가중 평균한다
- 적중 = `sign(실현) == sign(등급)`
- `|실현| < 0.5%`(bonds는 `< 3bp`)는 **무판정** — 잡음에 점수를 주지 않는다
- **등급 0(중립)은 분모에서 제외**하되, 「무포지션 비율」을 반드시 함께 인쇄한다.
  그러지 않으면 중립만 유지해 무패를 만들 수 있다
- **가중 점수** = `Σ(적중 ? +|등급| : −|등급|) / Σ|등급|`, 범위 −1 ~ +1.
  확신(±2)이 틀리면 더 크게 깎인다
- `scorecard.jsonl`에는 **주간 행만** 쌓는다. 월간 스코어카드는 그 달의 주간 행을
  롤업해 만들며 별도 행을 쌓지 않는다(같은 기간을 두 번 세지 않기 위해)
- 누적 구간은 span에 따라 다르다 — 주간은 **4주·12주·전체**, 월간은 **3개월·12개월·전체**

**레짐 채점**은 별도다. 그 기간 신규 발표 지표들의 `direction`(`macro_metrics.json`이
이미 계산해 둔 값 — writer가 z를 만지지 않는다는 규율의 연장)이 현재 레짐과 정합인지
«정합 / 불일치 / 판정불가» 3값으로 판정하고, 판정불가는 신규 발표 0건일 때다.

**트리거 위생**도 산출한다:

- 그 기간 발동한 트리거와 발동 후 실현치
- **연속 미발동 일수가 20거래일을 넘긴 트리거** — 임계가 너무 빡빡해 사실상 죽은 조건

**서술 규율**: 틀린 것부터 쓴다. 맞은 것 나열은 금지한다. 틀렸을 때는 «트리거는 옳았는데
시장이 따라오지 않았나» 와 «트리거 설계가 틀렸나»를 구분한다.

## 복기 (KR)

KR에는 승계 책이 없어 같은 채점이 불가능하다. 이번 범위에서는 **정성 복기 + 사실 대조**로
둔다 — 그 기간 지수 방향, 수급 주체별 누적, 업종 breadth가 주초 서술과 어긋난 지점.
US와 비대칭이라는 사실을 리포트에서 숨기지 않는다. KR 스탠스 책 도입은 후속 과제다.

## 발행본 회수 — 주 소스

`scripts/us/recap_source.py`가 그 기간의 발행본을 읽어 작성 에이전트가 쓸 재료로 만든다.
**HTML을 통째로 넘기지 않는다** — 주간 5편이 34K토큰씩이라 그대로는 컨텍스트가 감당하지
못한다. 발행본 하나에서 뽑는 것은 넷이다:

- `date` — 발행본의 거래일
- `headline` — 목록 JSON(`posts.json` / `kr/posts.json`)의 헤드라인
- `sections` — `<section>` 단위로 제목과 첫 문단(각 섹션이 그날 무엇을 말했는지)
- `figures` — 그 발행본의 수치 토큰 집합. 게이트가 허용 집합을 만들 때 쓴다

산출은 `recap_source.json`이고, 스키마는 `{"span", "key", "start_date", "end_date",
"posts": [ {date, headline, sections: [{title, lead}], figures: [...]} ]}`이다.
발행본이 한 편도 없으면 발행 중단이다 — 총정리할 원본이 없다는 뜻이므로.

## 리포트 구조

디자인·문체·반응형 규격은 기존 일간과 동일하다(Toss 시스템, `.tbl-scroll`, 1120px,
`word-break: keep-all`, 한 문단 한 주제). 세부는 `.claude/agents/brief-report-writer.md`를
따른다.

**US 주간 정리**

1. 헤드라인 — 그 주를 한 문단
2. 이번 주 성과 — 지수 6종 / 섹터 11종 주간 순위 / 커브 주간 bp 변화 / FX·원자재·메모리·AI 인프라.
   **유일하게 집계 파일에서 채우는 절**
3. **그 주에 무슨 일이 있었나** — 이 리포트의 본체. 발행본 5편을 요일 순으로 관통하며
   촉매와 그 귀결을 잇는다. 5편의 요약을 나열하는 것이 아니라 **한 편의 서사로 묶는다** —
   월요일에 던져진 질문이 목요일에 어떻게 답해졌는지가 보여야 한다
4. **복기** — 스코어카드 표(7행) + 가중 점수 + 4주·12주·전체 누적 + 레짐 정합 + 트리거 위생
5. 다음 주 — 발행본이 이미 예고한 일정·트리거만. 새로 조사하지 않는다

**KR 주간 정리**

1. 헤드라인 2. 이번 주 성과(코스피·코스닥, 업종, 거래대금 상위 기간 합산)
3. **주간 수급**(외/기/개 누적, 확정치만, 합산 일수 명시) 4. 그 주에 무슨 일이 있었나
5. 정책·정치 촉매 주간 정리 6. 복기(정성) 7. 다음 주

**월간 정리** — 주간과 같은 골격이되 3절이 「그 달에 무슨 일이 있었나」가 되고, 발행본이
20편 안팎이라 요일이 아니라 **국면 단위로 묶는다**(달을 관통한 흐름 2~4개). 월간에만
있는 셋을 더한다:

- 섹터 로테이션 — 월간 순위 변동
- **레짐 궤적** — 한 달간 국면이 어디서 어디로 갔나 (`macro.jsonl`)
- **스탠스 등급 궤적** — 7개 자산군의 등급 이동 경로 (`stance.jsonl`)

이 셋은 주간 시계에서는 거의 움직이지 않아 월간에서만 의미가 생긴다.

## 실행 구조

기존 수집 워크플로 둘을 확장한다. 새 워크플로는 만들지 않는다.

- `collect-market-data.yml` → `scripts/us/period.py`, 승계 로그 append
- `collect-kr-data.yml` → `scripts/kr/period.py`

**클라우드 루틴 트리거 2개를 신설한다.**

| 트리거 | cron (UTC) | KST | 하는 일 |
|---|---|---|---|
| `weekly` | `0 0 * * 6` | 토 09:00 | US 주간 → KR 주간, 2편 |
| `monthly` | `30 0 1,2,28,29,30,31 * *` | 해당일 09:30 | 월 롤오버 판정 후 해당 시 US·KR 월간 2편 |

토요일 09:00은 US 일간(08:00)이 끝난 뒤다 — 금요일 발행본이 이미 올라가 있어야 총정리할
원본이 갖춰진다. 금요일 수집 실행(22:15 UTC = 토 07:15 KST)도 그 전에 끝나 있다.
월간 트리거는 월말 근처 6~7회만 돌고, 대부분은 롤오버 판정 후 즉시 종료한다.

트리거에는 짧은 부트스트랩만 넣고 파이프라인은 레포 파일에 둔다(기존 규칙):

- `.claude/WEEKLY_ORCHESTRATOR.md`, `.claude/MONTHLY_ORCHESTRATOR.md`
- `.claude/agents/period-report-writer.md` — `market=us|kr`, `span=weekly|monthly`
  파라미터 하나로 4종을 처리한다

## 발행 게이트

`scripts/us/period_gate.py` (로직) + `scripts/check_period.py` (CLI):

1. **수치 대조** — 발행본의 숫자 토큰이 «해당 기간 집계 파일 ∪ `scorecard.json` ∪
   `recap_source.json`의 `figures`»의 합집합에 실재하는지. 순위처럼 파생되는 값은
   집계 파일이 미리 계산해 담아 두고 게이트는 그것과 대조한다. 에이전트가 즉석에서
   산술한 수치는 통과하지 못한다
2. **스코어카드 대조** — 적중률·가중 점수·누적이 `scorecard.json`과 정확히 일치
3. `[확인필요]` 금지
4. 금지 어휘 — `buy-side`/`buy side`/`바이사이드` (기존 `BANNED_LABELS` 재사용)
5. 내부 파일명·용어 노출 차단 — `weekly.json`·`scorecard.json`·`recap_source.json`·
   `_sessions`·`signed-z` 등
6. 커버 기간 명시 — 시작·종료 거래일과 거래일 수가 본문에 있을 것
7. 반응형 — 390 / 1280px에서 `scrollWidth == 뷰포트폭`
8. **발행본 커버리지** — 그 기간 발행본의 **모든 거래일이 본문에 언급될 것**. 총정리인데
   특정 날을 통째로 빠뜨리면 그 날의 사건이 사라진다

## 아카이브·SEO

`scripts/update_archives.py`가 목록 JSON 4종, `index.html`, `kr/index.html`,
`sitemap.xml`을 갱신한다. 기존 `/posts/` URL은 손대지 않는다.

**네비 구조** — 상단 메뉴바는 「미국 시장 · 한국 시장 · 메모리 thesis」 3탭을 유지하고,
미국·한국 각 index 안에 **일간 / 주간 / 월간 서브카테고리**를 둔다. 서브카테고리는
URL을 바꾸지 않는 in-page 전환이고(기존 50여 편의 링크 무손상), 현재 선택은 밑줄로
표시해 상단 메뉴바의 시각 언어를 따른다.

**sitemap은 재생성이 아니라 병합 upsert한다.** 현재 sitemap은 `<lastmod>`·`<changefreq>`를
달고 있고 `/thesis/` 항목을 포함하며, 세 오케스트레이터가 각자 갱신한다. 전체 재생성은
다른 파이프라인의 항목을 지운다 — **모르는 URL은 건드리지 않는다**가 유일하게 안전한
규약이다.

1. **승계 로그** — `history/*.jsonl` append + `backfill_history.py` ✅ 완료
