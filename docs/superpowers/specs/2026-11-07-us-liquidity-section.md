## 계약

1. **세션 창** `W(S) = (직전 거래일 17:30 ET, S 17:30 ET]`. H.4.1 발표 시각 = 제목 날짜 16:30 ET, QRA = 랜딩 시각(문서의 `<time>` 과 60초 안에서 일치해야 한다).
   **EFFECTIVE** = `config/liquidity.json` `effective_session` 세션 창의 **시작**(첫날 16:30 발표 포함). 없으면 기능 꺼짐(`disabled`).
2. **원장 = 발행본.** 현재 후보 `posts/<report_date>.html` 만 뺀 커밋된 US 일간 전부의 `data-h41-release`·`data-qra-doc`(주석 제외, 날짜 역순 발행도 본다).
   별도 상태 파일·발행 커밋 쓰기 없음 — v3 의 `expected.json`·`published.json` 은 글과 어긋나는 경로를 계속 낳아 폐기(codex 3차).
3. **H.4.1 후보** = 검증 회차 중 EFFECTIVE < 발표 ≤ S 기준시각이고 원장에 없는 것, 발표일 오름차순 **최대 3**. 만료 없음(사용자 「늦은 발표도 실어야 한다」로 v4 의 정한 손실·v6 의 21일 만료 폐기).
   14일 넘으면 경고. 발표 시각 ∉ W(S) 면 `late` → 캡션 「지난 발표분 —」.
4. **H.4.1 수집**: 매 실행 current + `expected_thursdays`(EFFECTIVE **직전** 목요일부터 — 그 목요일이 휴일이면 금요일 발표가 EFFECTIVE 뒤일 수 있다)마다 이력에 없는 주를 ±2일 아카이브 URL 로 다시 찾는다. 커서 없음. 못 찾으면 `pending`(경고, exit 0).
5. **QRA**: 가장 최근 회차만. 문서마다 정체성·필수 필드(없으면 그 문서 실패)·선택 필드(있을 때만 쓸 수 있다). 차환일 = **같은 달 15일**(v1 의 「다음 달」은 오류 — 11/4→11/15 회귀).
   TBAC 는 `view`, 단독으로는 섹션을 열지 않는다. 새 회차가 옛 회차를 대체할 때 실리지 않은 옛 문서는 `superseded_unpublished` 경고(유일하게 버리는 경로).
   가이던스 비교 = 현재 회차보다 앞선 가장 최근 회차(자기 자신 금지), 없으면 `unknown` — 문단 금지.
6. **이례적** = 회차 시점의 직전 52개 유효 「수요일 잔고 주간 변화」(직전 행과 정확히 7일 간격일 때만 계산) 분포에서 |z| ≥ 2.00. n < 40 또는 SD < 10억 달러면 미판정. 계절성 필터 없음.
7. **실행**: 시작 때 `table.html`·`qra/*.txt` 삭제 + `running` → state(파일 하나, rename 한 번) → 책 `complete`. 원천 pending·실패와 무관하게 끝까지 돌면 complete.
   `--sanitize`(always) 가 이 실행의 complete 가 아니면 산출물만 비운다. 워크플로: 시장 수집이 skipped 여도 돈다 — 별도 「Commit liquidity」 단계.
8. **경합**: 게이트가 책의 `pool`·후보를 지금 원장으로 다시 계산해 다르면 `ledger_changed` → `--recompute`(네트워크 없음, 결정적) → 섹션만 재작성, 최대 2회.
   STEP 3 의 pull 뒤·rebase 마다 같은 게이트를 다시 돈다.

## 작성·게이트

작성 계약은 `.claude/agents/brief-report-writer.md` 6-c, 게이트 `scripts/us/liquidity_gate.py`. 게이트는 표(회차 집합·머리·셀·캡션), 표식 문단 정확히 하나,
문단 금액의 역할(행 이름 구간마다 그 행 값)·필수 값·방향어, 비교 월·방향, 가이던스 표식·낱말 인용, TBAC 견해 어휘, 무표식 문단, 「오늘」+수요일 값, 인과 단정 바닥선을 본다.
수치 전수 대조(`number_audit._delegations`)는 이 게이트가 통과할 때 섹션의 표·캡션·표식 문단을 위임받는다 — 게이트가 그 안의 **모든** 수치 토큰을 데이터와 맞추고 나머지 토큰은 거부하므로 요소 단위 위임이 정직하다.
**한계**: 바꿔 쓴 인과·반대 판정은 못 잡는다 — 발행 후 codex 검토 몫.

## 링크를 싣지 않는 이유 (codex 2차 #13 의 출처 연결 권고를 바꿔 반영)

리포트는 링크를 내지 않고 문장에 출처를 밝힌다(`source_gate` 원칙). 이 섹션도 링크를 싣지 않으므로 `check_sources.py` 승인 목록에 문서 URL 을 더하지 않았다 —
작성자가 링크를 넣으면 지금처럼 막힌다. 출처는 표 캡션(「출처: 연준 H.4.1」「출처: 미 재무부」)에 있다.

- **QRA**: 랜딩의 발표 묶음별 「The next release is scheduled for …」를 `state.schedule.qra_next` 에 둔다(11/2·11/4 회차 → 2027-02-01·02-03).
  그날이 되기 전에는 랜딩을 열지 않고, 지난 실행이 확인한 회차를 최신으로 본다. 다음 발표일을 모르거나 그날이 지났으면 확인하고,
  최신 회차에서 발표 시각이 지났는데 아직 검증 못 한 문서(월요일 확인 뒤의 수요일 성명, 검증 실패)가 있으면 다음 회차까지 기한 없이 다시 받는다. 검증한 원문은 state 에 두고(최신 회차만) 확인하지 않는 날에도 `qra/*.txt` 로 다시 쓴다.
- **정한 위험**: 재무부가 발표일을 앞당기면 원래 예정일까지 모른다(랜딩을 열지 않으므로). 늦추면 예정일부터 매 실행 확인하다 찾는다.
- 책 `checked: {h41, qra}` 가 그 실행이 실제로 페이지를 열었는지, `schedule` 이 다음 예정일을 보인다.
