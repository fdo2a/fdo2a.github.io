# thesis 감시 — 조용한 날 사전 확인 (2026-09-24)

## 문제

thesis 감시는 「대부분의 날에 아무것도 하지 않는다」가 정상 결과다. 그런데 그 결론에 이르려고
매일 두 에이전트가 같은 일을 했다.

- Claude 루틴 `trig_01KfzghhVx3qa9eBEVjEg8Sy`(평일 19:00 KST, sonnet-5) — 런북·DESK_REPORT 를
  읽고 웹 리서치.
- codex 자동화 `~/.codex/automations/thesis`(평일 18:00 KST, reasoning high) — 같은 런북을
  같은 방식으로. 설정 경로가 없어서 매번 대체 경로부터 찾았고, `memory.md` 에 「변화 없음」
  기록만 49 KB 쌓였다.

8/24~9/23 사이 실제 변화는 2건(8/27 Micron, 9/9 삼성). 두 계정의 한도는 US·KR 브리프와 발행 후
검토가 함께 쓴다 — 2026-09-23 에는 Claude 주간 한도 소진으로 루틴이 시작 즉시 거부됐다.

## 결정

1. **codex 자동화를 멈춘다**(status PAUSED). 레포의 설계는 Claude 루틴이고 게이트·런북이 그쪽에
   맞춰져 있다. codex 한도는 발행 후 검토 러너가 쓴다.
2. **모델 호출 전에 산술로 「조용함」을 증명한다.** `scripts/thesis_quiet.py` → `quiet.decide()`.
   - 수치 트리거: 런북 STEP 1 과 같은 계산.
   - 확정 공시: `disclosures.json` 의 `confirmed_count`(DART 화이트리스트).
   - 뉴스룸: `events.json` — Actions 수집기가 삼성(반도체·기업)·SK하이닉스(보도자료·IR) RSS 에서
     **직전 수집 시각 이후** 항목만 기록한다. 날짜 창이 아니라 시각 창이라, 17:40 수집 뒤에 올라온
     항목이 이튿날 한 번만 잡힌다.
   - 실적 발표 창: 어느 종목이든 `next_earnings_date` −1~+2일.
3. **증명할 수 없으면 조용하지 않다.** 입력이 오늘 것이 아니거나 불완전하면(`missing`, DART 키 없음,
   파일 없음) `THESIS_CHECK`. 틀린 「조용함」은 사건을 놓치고, 틀린 「조용하지 않음」은 평소 실행
   한 번 비용이다.
4. **금요일은 전체 점검.** Micron IR 피드와 SEC submissions API 는 이 클라이언트를 403 으로 막았고
   (2026-09-24 실측), 고객사(NVIDIA·AMD) 뉴스룸은 공급사를 거의 안 밝혀 매일 받을 가치가 없다.
   이 둘은 주 1회 사람처럼 훑는 것으로 메운다. Micron 실적은 실적 창이 잡는다.

## 경계

- 뉴스룸 피드는 비-코어다. 실패는 `missing` 에 남고 그날을 `THESIS_CHECK` 로 만든다. 수집을 막지 않는다.
- 뉴스룸 항목은 **등급을 움직이지 않는다.** 리서치를 부를지 정할 뿐이다. 등급은 여전히 STEP 2~3
  의 1차 출처 규칙과 `propose()` 가 정한다.
- 피드에 잡히는 항목 상당수는 thesis 와 무관한 홍보성 글이다(삼성 기업 범주). 그런 날은
  `THESIS_CHECK` 가 되고 루틴이 평소대로 판단한다 — 키워드로 거르지 않는다. 거르다 놓치는 쪽이
  더 비싸다.
