# 뉴스·산업 브리프 — 시황 브리프에서 네 섹션을 떼어 둘째 글로 (2026-09-26)

## 사용자 지시

「오늘의 뉴스, 메모리/DRAM, AI 인프라, MLCC에 이번에 새로 추가한 것들을 모아 시황 레포트에서 제외시킨 뒤, 그냥 새로운 글을 하나 더 만드는 방향으로 바꾸자」.

설계를 가르는 질문 둘에 대한 답(같은 날):
- 누가 쓰나 → **기존 US 루틴이 두 편을 쓴다**(새 루틴 없음 — 주간 한도, 이미 읽은 데이터·리서치 재사용).
- KR 뉴스 → **「kr은 그냥 기존대로 하나의 레포트에 포함」** — KR 은 바꾸지 않는다.

## 사각지대 점검에서 나온 것 (설계 입력)

1. 수집 시각이 갈린다(US·글로벌 뉴스 06:30 KST, KR 17:00) — KR 을 그대로 두면서 해소.
2. 새 루틴의 토큰 비용 — 기존 루틴의 둘째 산출물로 해소. 둘째 글은 윤문(STEP 2.5)을 하지 않는다: 뉴스 블록은 `summary_ko` 유사도 게이트에 묶여 있고 산업 세 섹션은 짧다.
3. 메모리·AI 인프라의 업계 뉴스는 루틴의 웹 리서치(`research_notes.md` ③·④)에서 온다 — 수집 담당은 그대로 두고 둘째 글 작성자에게 넘긴다.
4. 사이트 배관 — 셸·목록·sitemap·검토 큐.
5. 산업 섹션의 주기(주간이 맞을 수 있다) — 사용자가 「기존 루틴이 두 편」을 골라 일간 유지.

## 결정

| 항목 | 결정 |
|---|---|
| URL | `/news/<report_date>.html`, 목록 `news.json`, 홈 「뉴스·산업」 탭 |
| 셸 | `post_shell.MARKETS['news']` — CSS·상단 바는 US 와 같고, 네비에 「같은 날 시황 브리프 →」 |
| 작성 | `.claude/agents/news-industry-writer.md`(오늘의 뉴스·MLCC 상세 사양과 팩터 분해 규칙을 옮겨 왔다). 웹서치 없음 |
| 순서 | 시황 브리프가 먼저 발행된다. 둘째 글이 게이트를 못 넘으면 브리프만 나간다 — 그래서 둘째 글의 「시황 브리프」 링크는 끊기지 않는다 |
| 게이트 | 둘째 글: `check_news`·`check_readability --strict`·`check_style`·`apply_colors`. 시황 브리프에서 `check_news` 를 뺐다. `check_sources` 는 둘째 글에 돌리지 않는다 — 뉴스 원문 링크를 허용하는 쪽은 뉴스 게이트다 |
| 완성본 규칙 | 메모리·AI 인프라 표 누락은 둘째 글만 막는다 |
| 검토 | `review/queue.py` 는 모르는 디렉터리를 원고로 센다 — `news/*.html` 은 자동으로 미검토 큐에 든다. 무인 정정 러너는 us·kr 만 돈다 |
| 번호 | 시황 브리프 §11·§13~15 번호는 다른 문서가 가리켜 비워 둔다 |

## 같이 고친 기존 결함

US 루틴 STEP 3 은 `sitemap.xml` 을 `posts.json` 으로 **재생성**했다 — 주간·KR·thesis(그리고 이제 뉴스) URL 이 매일 아침 지워진다. `scripts/us/archives.py` 머리말이 금지한 바로 그 방식이다. `update_archives.py --kind daily` 로 병합하게 바꿨다(항목 열쇠는 기존대로 `date`).
