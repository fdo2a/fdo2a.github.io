# 텔레그램이 발행 전 기록을 읽는다 — 2단계 (2026-11-08)

## 왜

1단계(`2026-11-08-prepub-record.md`)는 US·KR 일간 발행 커밋에 `verification/<m>/<D>.json` 을 남긴다. 그 기록을 사용자가
보지 못하면 「검증 장치가 있다」는 말은 증명되지 않는다. 사용자 결정(11/08): A안 — 발행 건별 알림(5분) + 기존 09시 매일 요약.
루틴·게이트·기록 형식은 바꾸지 않는다. 텔레그램 토큰은 맥 키체인만(클라우드에서 보내지 않는다). 대시보드·새 검사 없음.

## 구성

| 파일 | 몫 |
|---|---|
| `scripts/verification/repo_check.py` | 맥이 직접 하는 짝 확인. 루틴의 `record.verify` 와 **다른 함수**(루틴 경로 무변경) |
| `scripts/review/prepub_view.py` | 글 하나의 상태 계산·문장 — 발행 건별 알림과 매일 요약이 함께 쓴다 |
| `scripts/review/publish_watch.py` | 5분 회차의 판단: 기준점·사건·미발행·전송 |
| `scripts/verify_publish.py` | 진입점(`runner_launch.py publish`), 상태 `~/Library/Application Support/fdo2a/verify_publish.json` |

매일 요약(`verify_digest.py`)과 **상태 파일·실행 경로·전송 이력이 따로**다. 요약은 발행 상태를 읽기만 한다(꼬리 줄).

## 두 사실을 따로 낸다

- **[맥이 직접 확인]** 범주마다 일치/불일치/대조 불가: 글 지문, 검사기 목록(**기록 커밋의 설정** 기준 — 지금 설정과 비교하면
  검사기가 늘 때마다 과거 기록이 불일치가 된다), 검사 코드, 레포 안 코드·원장 다이제스트, 레포 보존 입력(`repo:`),
  작업 공간 전용 입력(항상 대조 불가). 불일치가 하나라도 있으면 「불일치」, 대조 불가가 있으면 「일부 확인」 — **「일치」라고 하지 않는다.**
- **[루틴이 남긴 검사 결과]** 기록 그대로: 판정·발행 가능·검증 완료·필수 통과 수·막은 것·판정 불가·실행 안 함·일부만·노트 수치·
  참고 실패·경고·숫자 대조 수. 요약 필드가 없으면 「통과」로 보지 않는다.
- 맥은 짝만 다시 본다. 검사가 실제로 돌았다는 것은 루틴의 자기 기록에 기댄다. 같은 데이터·같은 검사 논리라 원자료 자체의
  오류는 발행 전·후 모두 놓친다 — 「두 겹 검증」이라고 하지 않는다.

## 기준 판과 정정

- 기준 = 그 날짜 **기록 파일을 처음 담은 커밋**. 「처음 공개된 판」이라 부르지 않는다(git 그래프는 공개 시점을 증명하지 못한다).
  글을 추가한 커밋과 다르면 그렇게 적는다. 글·기록을 추가한 커밋이 2개 이상(지웠다 다시 추가)이면 판정 불가.
- 그 뒤 판은 짝 경보를 만들지 않는다. 이웃 판끼리 `review.prose.typography`(root 없이): True 조판, False **조판 외 변경**
  (본문 정정이라 단정하지 않는다), None·merge·삭제 = 판정 불가. 정정은 발행 건별 알림을 만들지 않고 요약에만.

## 5분 회차

- 기준점은 **마지막으로 정상 확인한 원격 커밋**(`last_seen`) — 시간이 아니다. `last_seen..tip` 에서 바뀐 대상만 다시 계산.
  기준점이 지금 이력의 조상이 아니면 「그 사이를 다 봤다고 할 수 없다」 알리고 전부 다시 계산.
- 조회(fetch·읽기) 실패: 기준점을 옮기지 않고 미발행 판정도 하지 않는다. 마지막 정상 확인 2시간 뒤 한 번 알리고, 복구되면 알린다.
- 미발행: `routine_due.us_session/kr_session` + **그 커밋의** 휴장 달력. 기준 시각 US 세션 D → D+1 12:00 KST(금요일 → 토요일),
  KR D → D 23:00 KST. 「원인: 확인 불가」 — 「보류」라 단정하지 않는다. 경보 뒤 글이 오면 「미발행 해소」. 미해소 세션은 기한 없이 보존.
  달력을 못 읽으면 그 시장의 판정을 멈춘다(빈 달력 = 휴일을 거래일로 보는 거짓 경보). 달력에 없는 휴장일은 여전히 거짓 경보.
- 사건 식별자는 내용에서 정해진다(같은 사건 = 같은 식별자). 저장 → 전송 → 저장. 보낸 뒤 저장이 실패하면 다시 보낸다 —
  **재전송 시 중복 가능, 유실 없음**. 전송 실패는 pending 으로 남겨 같은 식별자로 재시도(순서 유지).
- 상태 파일 손상 → 따로 옮기고 새로 시작, 적용일 이후 전부 다시 계산(이미 받은 알림이 다시 올 수 있다고 알린다).
- 5분은 맥이 깨어 있고 네트워크가 될 때의 목표. 런처(`runner_launch.py`, 검토 러너와 공용)는 바꾸지 않았다 — 런처·맥·텔레그램이
  함께 죽으면 실시간 알림은 없고, 매일 요약이 「마지막 정상 확인 n시간 전」으로 늦게 알린다.
