# moomoo OpenAPI 보조 입력 설계 (2026-09-22)

사용자 지시: moomoo OpenD 를 설치하고, 미국 리포트에 붙일 수 있는 것은 전부 붙인다.

## 왜 붙이는가 — 웹서치 산문이던 칸 둘

`.claude/agents/brief-data-collector.md` 가 스스로 적어둔 문장이 출발점이다.
「미확정으로 남는 것은 Forecast(컨센서스)와 비FRED 지표뿐」, 그리고 「CME FedWatch
금리 경로 수치(검색 1~2회)」. `scripts/us/calendar.py` 의 머리말은 더 직설적이다 —
「앞으로」를 담당하던 두 재료가 **둘 다 에이전트 웹서치 산문이라 전일 값도 없고
게이트도 검사하지 않았다」.

거기에 `data/fomc_dates.json` 은 **계약만 있고 파일이 없었다**. `scripts/build_calendar.py`
가 이 파일을 읽고 없으면 FOMC 항목을 빼고 `missing` 에 적는다. 그래서 블랙아웃 창과
SEP 분기 판정이 계산식을 갖고도 매일 돌지 못했다.

## 무엇을 붙이지 않았는가

**시세 수집 대체는 처음부터 배제했다.** 파이프라인 티커 44개 중 18개를 moomoo 가
지원하지 않는다 — 대만 3(시장 자체가 없다), 한국 3, 중국 A주 2(본토 인증 계정만),
FX 4, 상품선물 4, DXY. 그리고 가격 출처를 둘로 만드는 순간 「기록값은
`market_data.json` 하나」 원칙이 깨진다.

**미국 옵션 심리(풋콜레이시오)도 못 붙인다.** 실측에서 `get_option_market_statistic`
가 `Insufficient quote permission for US MarketOptions` 를 반환했다. 계정에 미국 옵션
권한이 없다. 실적 캘린더에 실리는 종목별 IV 는 다른 경로라 들어온다.

## 실측 제약 (2026-09-22)

- OpenD 10.11.7108, moomoo-api 10.11.7108. 계정 권한: US 주식 LV2, HK LV1.
- 구독 쿼터 100, 히스토리 캔들 100종목/7일. **FedWatch·캘린더 계열은 둘 다 소모하지
  않는다.** 호출제한만 걸린다(경제 캘린더에서 「Maximum 60 times per 30 seconds」 실측).
  엔드포인트별 상한표가 문서에 없어 `CALL_GAP_SEC = 1.2` 로 보수적으로 띄웠다.
- 실적 캘린더는 **조회 구간 상한이 7일**이고 **양끝을 포함**한다. `today + 7` 은
  8일이라 `ret=-1: Date range must not exceed 7 days` 로 죽는다. `today + 6` 이 맞다.
- 경제 캘린더는 한 페이지가 최대 100건이고 다음 페이지 표식을 준다. 한 페이지만 받고
  `ok` 라 적으면, 범위 안에 있으나 받지 못한 지표가 「그날 발표가 없었다」와 구별되지
  않는다 — 그래서 `partial` 로 내린다.

## OpenD 는 CI 에서 못 돈다

OpenD 는 로그인된 macOS GUI 세션을 요구한다. GitHub Actions 러너는 매 실행마다 새
기기라 기기잠금 인증이 반복된다(기기 ID 는 `Device.dat` 에 저장되고 러너는 매번
새로 뜬다). 증권계좌 로그인 자격증명을 CI 시크릿에 넣는 선택지는 배제했다.

그래서 `scripts/collect_moomoo_forward.py` 는 **로컬 전용**이다. 맥에서 돌고, 결과를
레포에 커밋해 클라우드 루틴이 읽는다. 맥이 꺼진 날은 파일이 갱신되지 않고, 파이프라인은
기존 웹서치 경로로 떨어진다.

## codex 설계 검토에서 바뀐 것

첫 설계는 「파일이 있으면 읽는다」였다. codex 검토(읽기 전용, 전문 28,273 B)가
지적 11개 중 P1 여덟 개를 냈고, 그중 다섯이 설계를 바꿨다.

### ① 파일 존재는 승인이 아니다

맥이 꺼졌다고 파일이 사라지지 않는다 — **어제 파일이 그대로 남는다.** 그래서 수집시각
(`fetched_at`)과 원자료 기준시각(`source_as_of`)을 분리하고, 대상 세션(`session`)이
정본 `report_date` 와 같을 때만 승인한다. 원천 시각을 모르면 `None` 으로 남긴다 —
수집시각으로 대체하면 격주 갱신 자료가 매일 새 자료로 보인다.

상태 어휘는 여섯이다: `ok / empty / partial / unavailable / stale / invalid`.
**정상 0건(`empty`)은 조회가 성공하고 범위가 확인될 때만 인정한다** — 범위를 모르면
그것은 0건이 아니라 모르는 것이다.

### ② 확률은 사건에 묶여야 비교된다

지금까지 `macro_gate` 는 `macro_next.policy_path.prob_pct` 의 존재와 본문 인용만
검사했다. 에이전트가 만든 수치를 에이전트가 만든 장부와 대조하는 구조라, 다음 회의가
바뀌었거나 특정 구간 확률과 누적 확률을 섞었어도 통과했다. 전일 대비 15%p 규칙
(`PROB_JUMP_PP`)이 그 차이를 「시장이 움직였다」로 읽어 정책 시점 변경을 정당화한다.

그래서 확률에 **회의일·목표구간 하단/상단·관측시각·공급자**를 묶었다. `macro_next` 는
`prob_meeting` 과 `prob_range_lower` 를 함께 적어야 하고, `_check_prob_source()` 가
승인 장부의 값과 대조한다(허용 오차 0.05%p). 분포 합계가 100 에서 1%p 넘게 벗어나면
**버린다 — 통과시키려고 정규화하지 않는다.** 같은 구간이 두 번 오면 거절한다.

`probability_delta()` 는 **같은 사건·같은 공급자**일 때만 값을 준다. 아니면 `None` 이다.
공급자 교체를 시장의 확률 변화로 오해하지 않기 위해서다.

### ③ 정책 확률 필수 규칙에 명시적 면제를 뚫었다

원천이 moomoo·웹 둘 다 없는 날까지 숫자를 요구하면 지어내라는 말이 된다. 그래서
`prob_status` 가 `unavailable` 또는 `unverified` 이고 `prob_note` 에 사유가 있으면
`prob_pct` 없이 통과한다. **전일 확률을 복사하거나 0으로 채우면 여전히 실패한다.**

### ④ moomoo 는 연준이 아니다

`scripts/us/calendar.py` 는 넘겨받은 회의일을 출처 「연준 공표 일정」·상태 `confirmed`
로 **고정해 인쇄한다**. 검증하지 않은 출처를 그 자리에 넣으면 더 강한 출처로 둔갑한다.

그래서 `scripts/us/fomc_official.py` 가 federalreserve.gov 를 파싱해 정본을 만들고,
moomoo 회의일은 `cross_check` 에만 남는다. 출처가 어긋나면 **더 최근 것을 자동으로
택하지 않고 불일치를 기록한다.** 공식 확인에는 유효기간(기본 45일)을 두어, 미래 날짜가
하나 남았다는 사실을 최신 확인의 대용물로 쓰지 않는다.

실측 대조 결과 moomoo 회의일은 공식과 **일치했다**(2027-01-27 = 공식 1/26-27 의
마지막 날 등, `cross_check.agrees=True`). 일치한다는 사실이 출처를 바꾸지는 않는다.

파서는 두 가지를 원문에서 직접 읽는다. **SEP 여부는 별표(`*`)** 이고(`calendar.py` 는
회의 월 3·6·9·12 로 추정한다 — 계산상 보조 규칙일 뿐이다), **회의 마지막 날**이 성명
발표일이다. 통지투표(notation vote)는 성명·기자회견이 없어 블랙아웃·SEP 전제와 달라
기본으로 뺀다.

### ⑤ 직전 회의를 버리면 블랙아웃이 사라진다

블랙아웃은 회의 **다음 목요일**까지다. moomoo 가 주는 「다음 회의 8개」만 쓰면 막 끝난
회의가 응답에서 빠지는 순간 그 주 판정 근거가 없어진다. codex 가 재현했다 —
보고서 날짜 2026-09-17 에서 `[09-16, 10-28]` 이면 `blackout.active=True`,
`[10-28]` 만이면 `False`, **둘 다 `complete=True`**. 공식 일정은 과거 회의를 포함하므로
`fomc_official.book()` 은 전체를 싣는다(실측 54회).

## 세션 계약

발행은 **KST 화~토**다. 「평일」로 잡으면 미국 금요일장을 다루는 토요일 발행을 놓치고,
월요일 KST 실행은 미국 일요일이라 대상이 없다. `target_session()` 은 화~토에만 값을
주고, 주말과 `holidays` 를 건너 직전 미국 거래일을 돌려준다. 휴장 달력은 여기서 만들지
않는다 — 인자로 받는다.

시각 주의: NYSE 정규장 마감은 16:00 ET 이고, 기존 정본 수집 기준은 17:30 ET 다.
KST 로는 여름 06:30, 겨울 07:30 이다. 로컬 수집이 그보다 먼저 돌면 정본이 아직 없다 —
그럴 때는 잠정 세션으로 보관하고 **발행 때 `session_matches()` 로 매칭한다.** 늦게
깨어난 맥이 과거 보고서용으로 최신 데이터를 소급 포장해서는 안 된다.

## 컨센서스를 FRED 와 섞는 법

`normalize_consensus()` 는 **Forecast 칸만** 만든다. Actual/Previous 는 FRED 가 정본이라
내보내지 않는다 — FRED 최신치는 개정된 값일 수 있고 공급자의 previous 는 발표 당시
값일 수 있어, 둘을 섞으면 개정분이 「발표 서프라이즈」로 읽힌다.

**이름으로 잇지 않는다.** CPI 의 YoY 와 MoM, headline 과 core, GDP 속보와 수정치는
제목만으로 구별되지 않는다. `CONSENSUS_MAP` 허용목록에 없으면 버린다 — 잘못 붙인
Forecast 는 빈 칸보다 나쁘다. 미국 외 국가 행은 들어오지 못한다.

**원집계 벤더가 문서에 없다.** `vendor` 는 `None` 으로 남기고 임의의 기관명으로 채우지
않는다. 지면에 실을 때 캡션은 「Actual·Previous: FRED / Forecast: moomoo 제공 컨센서스,
원집계 벤더 미확인」 형태여야 한다.

## 보류한 것 — 항목 4~6

실적 캘린더·등급변경·공매도 잔고·세션 랭킹은 **수집만 한다.** 본문 자동 사용은
표시 단위와 검증 방법이 정해질 때까지 보류한다. codex 지적 그대로다 — 파일을 얻었다는
사실이 작성자가 안전하게 쓸 수 있는 입력 계약은 아니다. 실적은 회계연도·통화·GAAP/조정
기준이, 공매도는 잔고 기준일과 발표일 구별이, 세션 랭킹은 스냅샷 시각과 세션 종류가
계약에 들어가야 한다. 06:40 KST 의 진행 중 애프터마켓을 최종 순위로 쓸 수 없다.

## codex 구현 검토에서 다시 바뀐 것

1차 구현을 다시 검토받아 P1 여섯·P2 여섯을 받았다. 그중 실제로 코드를 바꾼 것들.

- **월을 걸친 회의를 오기하고 있었다.** `April/May 30-1` 의 발표일은 5월 1일인데
  `max(nums)` 로 뽑아 5월 30일이 됐고, `January/February 31-1` 은 2월 31일을
  만들다 행째로 사라졌다. 산출물에 실제로 `2024-05-30` 이 들어 있었다(정답은
  2024-05-01). 마지막 숫자가 첫 숫자보다 작으면 월을 걸친 것으로 읽는다.
- **하단만으로는 사건이 식별되지 않는다.** 같은 하단의 3.75–4.00 과 3.75–4.25 는
  다른 사건인데 `find_probability()` 가 하단만 맞췄다. 상단을 함께 본다.
- **시점 변경이 여전히 생 확률 차로 판정되고 있었다.** 전일 9월 회의 40% 에서
  오늘 10월 회의 100% 로 갈아타면 `abs(prob-old) >= 15` 가 성립해 정책 시점
  변경이 승인됐다. `same_event()` 로 회의·구간이 같을 때만 비교한다.
- **세션 라벨만 맞으면 며칠 전 응답도 승인됐다.** 관측 창(기본 36시간)을 두고,
  `--date` 로 과거 세션을 만들어 현재 응답을 소급 포장하는 것은
  `--allow-backfill` 없이는 막는다.
- **회차가 섞일 수 있었다.** 파일을 순차로 바꾸고 manifest 를 마지막에 쓰는데,
  개별 파일에 회차 표식이 없어 중간에 끊긴 조합이 소비 가능했다. 모든 산출물에
  `run_id` 를 박고 `check_macro.py` 가 manifest 와 대조한다.
- **스키마 오류가 정상 0건으로 바뀌고 있었다.** `_records('아무거나')` 가 빈
  리스트를 돌려주고 `query_range` 가 있으면 `empty` 가 됐다. 모르는 모양은
  `SchemaError` 이고 상태는 `invalid` 다.
- **페이지가 남았는데 매핑 0건이면 `empty` 였다.** 첫 페이지가 전부 허용목록
  밖이면 다음 페이지에 유효한 지표가 있어도 「범위 안에 발표 없음」으로 저장됐다.
  이제 `more` 면 매핑 건수와 무관하게 `partial` 이다.
- **한 종목 실패가 공매도 묶음 전체를 실패로 만들었다.** 종목별 실패를 모아
  `missing` 에 남기고, 일부 성공은 `partial` 이다.
- **휴장 건너뛰기가 헬퍼에만 있었다.** `data/us_market_holidays.json` 이 있으면
  진입점이 읽어 넘긴다. 없으면 건너뛰지 않고, 그 사실은 세션 대조에서 드러난다.

### 단계로 미룬 것 — 승인 원천 필수화

codex 는 **승인 원천이 없으면 확률 인쇄를 실패시키라**고 했다. 그대로 넣으면
기존 게이트 테스트 14개가 깨진다 — 지금까지 모든 날이 웹서치 확률로 발행돼
왔기 때문이다. 이것은 게이트가 아니라 **작성 계약**(`.claude/agents/`)을 함께
바꿔야 하는 광범위 수정이라 `site/AGENTS.md` 7단계 규칙 7 에 따라 쪼갰다.

지금 닫은 것: **파일이 있는데 승인되지 않은 날**(맥이 꺼져 어제 파일이 남았거나
세션이 어긋난 날)의 확률 인쇄는 막는다. 남은 것: 파일이 아예 없는 날. 이 경우는
기존 계약대로 통과하며, 그래서 spec 과 잎사귀가 「전일 복사·0 채움은 여전히
실패한다」고 적었던 것은 **사실이 아니었다** — 문구를 고쳤다.

## 열린 항목

- **표식 없는 확률 산문.** codex 가 확인했다 — 현재 달력 게이트는 표식 없는 산문을
  그대로 통과시킨다(`calendar_gate.py:88-89`). `<p>FedWatch 99.9%</p>` 를 빈 장부와
  검사하면 위반이 0건이다. `_check_prob_source()` 는 `macro_next` 에 적힌 확률만
  대조하므로, 본문에 표식 없이 인쇄된 다른 확률은 아직 걸리지 않는다. 확률 블록에
  표식을 강제하거나 승인 데이터에서 결정적으로 렌더링해야 닫힌다.
- **윤문 후 finalize 경로 재실행.** `.claude/ORCHESTRATOR.md` 의 STEP 2.5 이후 경로에서
  같은 입력으로 게이트를 다시 돌려야 한다.
- **전달 경로.** 로컬 커밋 → 클라우드 루틴 `git pull` 이 현재 전제다. `build_calendar.py`
  는 Actions 에서 도므로 `fomc_dates.json` 갱신은 **다음 수집 실행부터** 반영된다.
  FOMC 일정은 드물게 바뀌므로 하루 지연을 받아들인다. 일정이 바뀐 날을 놓치지 않으려면
  공식 재확인 주기(45일)보다 짧게 돌려야 한다.
- **승인 원천 필수화의 나머지 단계** — 파일이 아예 없는 날의 확률 인쇄. 작성
  계약을 먼저 바꿔야 한다(위 「단계로 미룬 것」).
- **전일 스냅샷.** `probability_delta()` 는 있지만 전일 승인 장부를 보관하지
  않는다. 지금은 `same_event()` 로 비교 가능성만 검사한다. 이벤트 전후 확률
  변화(`brief-data-collector.md:241`)는 하루 한 번 덮어쓰는 파일로는 못 낸다.
- **휴장 달력의 내용.** `data/us_market_holidays.json` 을 읽는 경로는 붙였지만
  파일을 아직 아무도 만들지 않는다.
