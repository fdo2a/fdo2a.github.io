# 발행 뒤 codex 문체 수정 — US·KR 일간의 STEP 2.5 대체 (2026-09-27)

## 지시

사용자: 「업로드 마지막에 codex가 문체를 검토하고 수정하도록 설정해」. 두 결정은 사용자가 골랐다.

- **어디서**: 로컬 러너(`scripts/review_gate.py run --correct`, launchd 매시)에 통합. GitHub Actions 는 OpenAI API
  키가 새로 필요해서 제외했다(codex 는 ChatGPT 로그인으로 돈다).
- **루틴 STEP 2.5(Claude `humanize-korean`)**: 빼고 codex 로 대체 — Claude 주간 한도 절약.

클라우드 루틴에는 codex CLI 가 없다. 그래서 문체 수정은 발행 **뒤에** 온다. 독자는 러너가 돌 때까지(맥이 깨어
있으면 한 시간 안) 초고를 본다. codex 한도에 막힌 날은 초고가 그대로 남는다 — 사용자가 이 교환을 골랐다.

## 범위

`posts/DATE.html`(us)·`kr/posts/DATE.html`(kr). 주간·월간·일본은 게이트 입력(agg·insight·recap)이 러너에 없어
STEP 2.5 를 유지한다. 뉴스 브리프는 원래 윤문 대상이 아니다.

## 흐름

1. 러너가 발행 커밋에서 글과 데이터를 스냅샷으로 꺼낸다(기존). 글은 **지금 공개된 판**(조판만 다를 수 있다)으로
   덮고, `prose_swap.extract` 로 `prose_in.txt` 만 둔다(사이드카는 두지 않는다 — 아래 검토 1). 문장 표본(`STYLE_EXEMPLARS.md`)은
   `origin/main` 에서 꺼낸다 — 기준은 지금 것이다. humanize 규칙은 공개 레포에 복사하지 않고 로컬 플러그인 경로를 읽힌다.
2. codex 호출은 **글당 한 번 그대로**다. `workspace-write`(스냅샷 안) 로 `prose_in.txt` 만 고치고, 마지막 답으로
   기존 사실·논리·문장 지적을 낸다. 첫 줄 `검토 판본: 윤문 후` — 지적이 고친 문장 기준임을 뒤의 Claude 가 안다.
3. Python(`scripts/review/style_pass.py`)이 main 을 새로 clone 해 HEAD 의 글이 검토한 SHA 인지 확인하고,
   `prose_swap.reinsert`(문단마다 숫자·영문 이름·판단 어휘·링크·닮은 정도 0.80·길이 0.5~2배)로 되꽂는다.
4. 게이트는 STEP 2.5 finalize 목록 그대로, 근거 datadir 는 **발행 커밋에서 새로 꺼낸 것**이다(codex 가 쓰기 권한을
   가졌던 스냅샷은 믿지 않는다). 연구 원장 게이트는 글의 `data-research-cycle` 로 돈다. 원본에서 이미 실패하던
   게이트는 **종료 코드와 출력이 같을 때만** 봐준다.
5. 통과하면 `문체: codex 윤문 — <path>` + 트레일러 `Style-Pass: codex <원 sha7>` 로 커밋하고 민다. 거절되면
   한 번만 rebase — 단 그 사이 **이 글**이 바뀌었으면 rebase 하지 않고 버린다(충돌 없는 병합이 가장 위험하다).
6. 푸시가 끝난 뒤에만 초안이 새 판의 이름을 받는다. 거부·무편집·푸시 실패면 옛 판 이름 — 오늘 경로 그대로다.
7. **원장은 건드리지 않는다.** 「지적 없음」도 Claude 정정 단계가 확인한 뒤 기록한다(REVIEW_GATE, 2026-09-10 지시).
8. `publish_commit()` 은 트레일러 **와** 태그 구조·수치 불변이 둘 다 참인 커밋을 건너뛰고, `corrector._typeset_only`
   도 같은 관계를 받아들인다 — 정정의 근거는 원래 발행 커밋의 데이터다.
9. `runner.json` 의 `style_log`(최근 20건)에 반영·미반영과 이유를 남긴다. 거부는 러너 오류가 아니다.

## 배포

launchd 는 `site/` 작업 폴더의 코드를 돌린다. 푸시만으로는 러너가 바뀌지 않는다 — `site/` 를 pull 해야 한다.

## codex 설계 검토 (2026-09-27) — 전부 수용

1. 에디터 노트 보호 → `extract` 가 애초에 안 뽑는다.
2. 태그+전체 수치로는 의미 반전·문단 교환을 못 막는다 → 새 판별기 대신 `prose_swap.reinsert` 재사용.
3. `corrector._gates` 는 STEP 2.5 목록보다 좁다 → STEP 2.5 목록 그대로.
4. codex 가 최신 clone 데이터를 근거로 오인 → codex 는 발행 커밋 스냅샷만, clone 은 Python 만.
5. 원본 실패 게이트를 이름으로만 허용 → 출력까지 비교.
6. 푸시 실패 시 초안 이름 → 푸시 성공 뒤에만 새 이름.
7·8. 무편집 경로·지적 기준 판본 → 옛 이름 유지, 계약 줄. 자동 원장 표시는 구현 중 REVIEW_GATE 규칙과 부딪쳐 뺐다.
9. STEP 2.5 참조가 여러 곳 → 두 오케스트레이터·writer 지시문·AGENTS.md 규칙 5 정리.

## codex 구현 검토 (2026-09-30) — 6건 전부 재현, 전부 수용

1. **치명** — 사이드카가 codex 가 쓸 수 있는 작업 폴더에 있었다. 기대값을 고치면 「개선→악화」가 통과했다.
   → 사이드카를 두지 않는다. `reinsert_partial` 은 기대값을 **공개판 HTML 에서 새로** 뽑는다.
2. **치명** — 개수만 보는 검사라 「100에서 200으로→200에서 100으로」·「상승할→하락할」·「않았다」 삭제·
   「삼성전자→현대전자」가 통과했다(STEP 2.5 `reinsert` 에도 있던 약점). → `reinsert_partial` 에만
   `_check_strict` 추가: 수치의 **순서**, 방향어(오름·내림)의 **부호 순서**, 부정어 개수, 아는 이름 개수.
   아는 이름 = 근거 데이터의 이름 필드 + 글의 표 행 머리(`style_pass.known_names`). 주간·월간의 통째 거부
   경로(`reinsert`)는 그대로 — 엄격해지면 윤문 전체가 버려진다. 실제 발행본 16편 무편집 왕복에서 헛걸림 0.
   **남은 틈**: 목록 밖 한글 명사·방향어 목록 밖의 반전은 닮은 정도(0.80) 검사에만 기댄다.
3. **중대** — `_after_style_pass` 가 문체 커밋의 존재만 봤다 → 그 커밋의 blob 에서 검토 SHA 까지가 같은
   blob 이거나 조판만 다를 때만 인정.
4. **중대** — rebase 뒤 게이트를 다시 안 돌렸다 → `_push(recheck=)` 가 rebase 된 코드로 원본·수정본을 다시 맞댄다.
5. **중대** — 일부·전부 미반영이면 지적이 공개되지 않은 문장을 인용한다 → 초안 앞에 `[문체 반영 상태]` 를 붙여
   정정 단계가 인용 불일치로 기각하지 않게 한다.
6. **경미** — 트레일러가 아무 줄에나 있어도 인정했다 → 마지막 줄 + 트레일러의 SHA 가 부모 blob 과 일치.

### 재검토 (2026-09-30) — 4건 수용

1. **치명** 독립된 「안」(안 된다) 누락 → 부정어에 낱말 경계로 추가.
2. **치명** 이름과 방향의 짝 교체(삼성전자↑·현대차↓ → 반대) → 개수 대신 **이름·영문 이름·방향어를 나온 순서대로** 비교.
3. **중대** rebase 사이 게이트 목록이 늘면 옛 목록만 재검사 → `style_pass.py` 가 바뀌었으면 버리고 다음 tick.
4. **중대** 「지수」 같은 일반어가 이름으로 잡혀 정상 윤문 거부 → 데이터 키는 name·members·item_name·stock,
   표는 데이터 행 첫 `<td>` 만(`<th>` 제외), 두 글자 이상.
