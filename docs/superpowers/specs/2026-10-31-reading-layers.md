# 읽는 층과 KR 복기 표 (2026-10-31 설계, 2026-11-02 적용)

정본 지시: `.claude/agents/brief-report-writer.md` 「보고서 구조」의 「읽는 층」, `kr-report-writer.md` §13, `.claude/TRADER_LEARNING.md` 「Writer output」. 코드 `scripts/common/post_parts.py`. 이 문서는 근거와 이력이다. 설계·codex 검토 표는 프로젝트 루트 `plan.md` 2026-10-31.

## 요청

10/30 US 일간·KR 일간 외부 평가: 「설명하는 본문과 참고용 데이터를 구분하라」 — PART 1 30초 요약 / 2 확인된 사실 / 3 분석과 해석 / 4 투자 판단과 향후 관찰 / 5 참고자료·복기. KR 「시장 판단과 복기」는 긴 문단 대신 표(기존 판단 / 현재 결과 / 다음 행동)로. 문장·문단 수준은 같은 날 `STYLE_EXEMPLARS.md` §12 로 따로 반영했다(`2026-10-31-structural-editing.md`).

## 네 안과 고른 것

A 표지 층(순서 유지) / B 유형 분해(문단을 사실·분석·판단으로 쪼갬) / C 판단 하강(섹션째 사실→분석→판단) / D 본문·부록 분리. **사용자가 판단을 위에 두기로 했다(2026-10-31) → A.** B 는 자산이 두 곳에 살아 평가가 1순위로 꼽은 중복을 되살리고, `weight` standing/cause·매크로 전달경로·§2 표식 게이트를 거의 다 다시 짜야 한다. C 는 판단 우선(DESK_REPORT, `readability.move_strategy_first`)을 뒤집는다. D 는 별도 페이지면 게이트·검토 원장 비용이 크고 같은 페이지면 A 와 같다.

## 결정

1. **층 머리만 넣고 순서는 거의 그대로.** 1층(헤드라인·전략 코멘트)은 머리가 없다 — 맨 위라 이름표가 필요 없고, 「30초 요약」 대신 「요약·판단」이 실제 역할이다. US 2·3·4층(오늘 확인된 것 / 해석 / 판단과 복기), KR 2~5층(오늘 확인된 것 / 해석 / 복기와 확인 일정 / 참고 자료). 층 대응표는 `post_parts.LAYERS`.
2. **머리는 셸이 넣는다, 새로 렌더하는 글만.** `apply_readability.py` 는 기본 glob 이 전 아카이브라 거기 넣으면 수백 편이 다시 쓰이고 검토 대기열이 터진다(2026-08-24·26·28 선례, `review/prose.py`). `post_shell.render` 가 `PARTS_FROM`(2026-11-02) 이후 날짜에만 `post_parts.mark` 를 부른다 — 이것이 날짜 스위치다. 아카이브 137편은 전부 `reading-map-v1` 마커가 있어 `inject_reading_map` 의 새 분기(머리가 있으면 층으로 링크)도 새 글에만 닿는다.
3. **층은 앞으로만 간다.** 순서를 어긴 섹션은 열려 있는 층에 붙는다(층을 되돌려 열지 않는다). 새 위치 게이트는 만들지 않았다(10/31 「게이트를 더하지 않는다」) — 작성 지시가 순서를 지킨다.
4. **머리 모양**: `<div class="part-head" id="part-N" data-part="N">이름</div>` — section 밖, 열고 닫힘 완결(`section_div_breaks` 통과), `<h2>`·`<p>`·숫자 없음. 게이트들이 「다음 h2 까지」를 구간으로 자르고 숫자를 세기 때문이다. CSS 는 `post_css/wayfinding.css`(인쇄 시 다음 섹션과 붙임, `scroll-margin-top`). 셸 CSS 가 바뀌었으므로 직전 판을 `post_css/legacy/*-2026-10-31.css` 로 보관 — `check_contested` 가 정정 창 안의 옛 글 스타일을 계속 믿게.
5. **US 「주목 섹터·종목」은 원자재 바로 뒤로.** 트렌드 유닛 점검과 복기 사이에 있으면 「판단과 복기」 층에 사실 섹션이 끼인다. 위치를 보는 게이트는 없다(`check_movers` 는 표식, `weight` 는 제목). 「섹터 기간별 수익률」은 사실 데이터라 2층에 둔 채 옮기지 않았다.
6. **에디터 노트**는 코드(`editor_note._insertion_point`, 전략 코멘트 뒤)가 정본이다. writer 의 「원자재 바로 뒤」 문구가 틀렸었다(US leaf 의 「§7」 은 옛 번호의 전략 코멘트로 맞다). 노트는 1층에 남는다.

## KR 복기 표 (T1)

- `<p data-lede="review">` 첫 문단은 그대로 — `stance_gate` 의 첫 문단·80자·`VERDICT_CUES` 계약을 건드리지 않는다.
- 열린 판단은 표 `판단(세운 날) | 오늘 결과 | 상태`, 행마다 `<tr data-hypothesis>`. `research_gate.Elements` 는 태그를 가리지 않아 ID 계약(빠짐·남음·빈 행)이 그대로 걸린다 — 테스트로 고정했다. **게이트가 보장하는 것은 ID 와 빈 행까지**다. 칸의 상태 어휘·숨김 행은 보지 않는다(문단형 때도 같았다).
- 조건 문구는 「향후 확인 일정」 한 곳(DESK_REPORT 「the only place the full list appears」). 셋째 칸은 상태 + 다음 판정일.
- **표 아래 문단은 표가 못 담는 것만** — 새 판단의 출발 값·잴 방법·보류 조건, 상태가 바뀐 이유, 상태와 상관없이 판정을 좌우하는 단서. codex 설계 검토 #2: 「상태가 바뀐 판단만 문단」으로 하면 10/30 의 「기준을 넘은 폭 0.34%포인트」「변동성 미보정」 같은 단서가 사라진다.
- 단서를 `<p>` 에 두므로 문체 게이트(`style.py`, `-다` 검사는 `<p>` 만)가 그대로 닿는다. 칸은 명사형 40자 이하라 종결 검사 대상이 아니고, 작업 어휘 검사는 원래 표 안도 본다(codex #4 — 설계안의 「표는 문체 검사 밖」 주장은 절반만 맞았다).
- 주간 정리 리드(`recap_source._hypothesis_lead`): 가설 문단이 없으면 첫 가설 행의 칸을 띄어 잇는다.
