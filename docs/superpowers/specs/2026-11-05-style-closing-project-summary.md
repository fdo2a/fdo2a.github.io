# 시황 브리프 문체 개선 프로젝트: 결정·진행 현황 (2026-11-05)

> **문서 성격:** 2026-11-05까지의 논의와 Claude Code가 보고한 C안 v2.2 설계를 요약한 기록이다. 구현 명세의 정본이나 구현 완료 증명은 아니다. 이후 설계 변경과 실제 구현 상태는 최신 계획·코드·검토 기록을 우선한다.

## 1. 결론과 목표

기존 **발행 후 Codex 윤문 및 자체 검토**를 **발행 전 Claude Code의 제한적 문체 마감 → `close_guard.py` 의미·범위 검사 → 발행 → 발행 후 Codex 읽기 전용 독립 검토**로 전환하는 C안을 선택했다.

목표는 짧은 문장을 억지로 잇는 것이 아니라, **원문의 사실·수치·판단·불확실성과 논리관계를 유지하면서 실제 독해 부담을 줄이는 것**이다. 수정이 도움이 되지 않으면 원문을 유지한다.

문장 수준의 마감은 C안이, **문단 배치·주제 중복·정보 과밀·인과 논증 등 구조 문제는 작성 단계의 §12 구조 편집**이 담당한다. 두 책임을 합치지 않는다.

## 2. 변경을 결정한 근거

- 발행 뒤 Codex 문체 수정 **제안 507건 중 판단 변경 10건(약 2.0%)**, 57편 중 8편에서 발견됐다. 그중 **8건은 연결어미 우선 규칙과 판정어 변경 규칙**에 관련됐다. 이 수치는 *제안의 판단 변경 비율*이지, 실제 발행본의 오류율이 아니다.
- 대표 위험: `뒷받침하는 쪽이다 → 뒷받침한다`처럼 확신 수준을 높이거나, 두 독립 사실을 `~하면서`로 이어 원문에 없는 인과를 암시한다.
- 2026-10-13 이후 발행 뒤 Codex 스타일 수정 제안은 실제 발행본에 반영하지 않았다(`style_pass.APPLY=False`로 보고).
- 작성 단계에서 이미 문장 끊김이 감소했다. **40자 미만 문장 비율**은 비교 표본(10/01~09 6편 vs 10/27~11/04 6편)에서 US 42%→27%, KR 28%→21%로 측정됐다. 이는 가독성 품질 자체의 증명이 아니라 길이 기반 보조 지표다.
- 최근 22편에서 **40자 미만 문장 2개 연속**을 포함한 문단은 글당 중앙값 5개, 최대 9개였다. 따라서 전체 원고를 다시 윤문하기보다 후보 문단만 검토하는 방식을 선택했다.
- 2026-09-27의 전체 Claude 윤문 STEP 2.5는 주간 사용 한도 부담으로 폐지됐다. 2026-10-22의 발행 전 번역투 점검은 세 차례 Codex 설계 검토에서 기각된 안을 거쳐 **작성자가 자기 초안을 마감 단계에서 수정하는 v4**가 채택됐다. C안은 이를 확대한다.
- 기존 구조 편집 감사에서는 반복, 문단 끝의 다른 주제 삽입, 과밀 문단, 인과 단정과 근거의 불일치가 확인됐다. 이는 최종 문체 마감만으로 해결할 수 없다.

## 4. 발행 전 문체 마감 계약 (C안 v2.2)

1. 문체 마감 시작 시 HTML의 **`.pre-close` 사본**을 생성한다. 수리 루프에서 마감 단계를 반복 실행하지 않는다.
2. 기존 `scripts/scan_translationese.py`에 `--flow` 후보 탐지를 추가한다. 같은 산문 문단에 **40자 미만 문장 두 개 이상 연속**일 때 검토 후보로 올린다. 인용·표·자동 생성·보호 구역과 잠금 판단 문장이 포함된 자리는 제외한다.
3. 40자 기준은 **수정 명령이 아니라 검토 후보 선정 기준**이다. 작성자는 다음 가운데 선택한다: 그대로 유지(기본값), 원문에 이미 명시된 관계만 연결, 의미를 유지하며 과밀한 문장 분리, 잠금 문장 유지.
4. 별개 사실·판단·반론·한계는 짧더라도 유지한다. 접속어·연결어미를 억지로 늘리거나 지시어를 구체명사로 바꿔 새로운 범위를 만들어서는 안 된다. 자연스러운 세 단문(외국인 순매도 / 기관·개인 순매수 / 코스피 하락)은 **그대로 유지**하는 예시로 쓴다.
5. 기존의 판정어 정리 지시는 **작성 단계**에 두고 최종 문체 마감에서 판단의 상태·강도를 바꾸지 않는다.
6. 긴 문장의 정보 과밀과 전체 배치 수정은 이번 후보 탐지의 직접 범위 밖이다. 초기 운영에서 탐지 누락 표본을 따로 조사한다.

## 5. `close_guard.py`와 실패 처리

**검사 순서와 효과**

1. 문단 밖의 HTML·표·링크·속성·생성 영역이 바뀌거나 문단 수·순서가 달라지면 **마감 변경 전체를 `.pre-close`로 되돌린다**.
2. 후보가 아닌 문단이 변경됐다면 **그 문단만 되돌린다**.
3. 후보 문단의 숫자 다중집합·순서, 부정어, 인라인 태그 자리표, 지시어 개수, 원장 앵커·날짜·기간과 판단·상태·확인 기준 어휘가 든 문장의 **원문 잠금**을 검사한다. 위반 문단만 되돌린다.
4. 후보 식별은 **문단 위치 번호 + 마감 전 원문 해시**로 한다. 해시는 후보 목록과 마감 전 사본의 일치 여부를 확인하며, 정상 수정된 결과 텍스트의 해시와 비교하지 않는다.
5. 검사 자체가 오류를 내면 **마감 전 사본으로 전체 복구**한다. 복구 불능(사본 소실 등)은 정상 발행 불가로 취급한다. 문체 경고를 일반적인 발행 차단 조건으로 승격시키지는 않는다.
6. 최종 보고는 번역투 잔존 수, 흐름 수정 문단 수, 원복 문단 수를 분리한다.

판단 잠금 규칙은 **기존 10건을 모두 잡았지만 그 사례를 보고 구성된 규칙**이다. 새로운 유형에 대한 일반적 보장은 아니다. 새 관계가 잠금 문장 밖에서 생성될 위험은 잔존한다.

## 6. 발행본과 비공개 수정 기록

클라우드 루틴과 Mac의 러너가 로컬 파일을 공유하지 않으므로 **비공개 GitHub 저장소 `fdo2a/report-close-edits`**를 수정 기록의 전달 경로로 선택했다. **저장소 생성은 보고됐으며**, 루틴 연동과 Mac의 deploy key 발급은 마지막 보고 기준 구현 대기였다.

- 공개 발행본에는 `<!-- close-edit: <record_id> -->`만 남기며, 수정 전후 문장은 공개 Git 이력에 넣지 않는다.
- 비공개 기록은 **record_id, 발행본 식별자, 최종 HTML의 Git blob SHA, 실제로 편집한 문단의 전후 텍스트 및 검사 결과**만 보관한다. 전체 초안은 보관하지 않는다.
- 공개 게시물 커밋이 확정된 뒤 **최종 blob SHA**를 비공개 기록에 저장해 순환 해시 참조를 방지한다.
- Claude GitHub 앱은 해당 비공개 저장소에 쓰고, Mac의 Codex 러너는 **해당 저장소 전용 읽기 전용 deploy key**로 가져온다. Codex 작업 폴더에 비공개 기록 파일을 복사하지 않고 필요한 전후 문단만 호출 입력으로 전달한다.
- 비공개 문장·자격증명이 공개 작업 트리나 로그에 남지 않는지 시험한다. 로그에는 record_id와 건수만 남긴다.
- 비공개 기록 푸시는 최대 3회 재시도한다. 실패해도 발행은 진행하며 Codex 기록에는 **`meaning_comparison_unavailable` / '원문 대비 의미 보존 미확인'**을 표시한다.
- 기록 생성과 공개 게시물 발견 사이의 지연을 고려해 기록 누락에 대한 제한적 재확인 경로를 둔다. 기록과 발행본 식별자가 일치하는지 검증하며, 기록 변경·재발행 시 과거 기록을 무심코 덮어쓰지 않는다.

## 7. 발행 후 Codex 검토와 정정

- Codex는 **읽기 전용**으로 최종 글의 문체 문제를 최대 5건 지적한다. 유형: 판단 세기 흐림, 근거 없는 논리 관계, 끊긴 흐름, 번역투, 반복. **고쳐 쓴 문장을 발행본에 직접 적용하지 않는다**.
- 원문 대비 의미 변경 판단에는 실제로 편집한 문단의 **마감 전후 비교**가 필요하다. 기록이 없으면 '변경 확정'으로 주장하지 않는다.
- **일반 문체 지적**은 주간 묶음으로 수집하고, 사람이 검토 후 `STYLE_EXEMPLARS.md`에 반영할지 결정한다. 자동 지시문 개정은 하지 않는다.
- **의미·판단 위험**은 기존 정정 절차로 즉시 넘긴다. Claude Code가 원문과 근거 자료를 대조해 실제 오류일 때만 복원·정정한다. Codex 지적은 자동 복구 명령이 아니다.
- 복원 직전 **현재 공개 발행본의 blob SHA가 기록의 SHA와 일치하는지** 확인한다. 다르면 최신 정정을 덮어쓰지 않고 **사람검토**로 전환한다.

## 8. 시험·측정·롤아웃

**독립 표본 회귀 시험**
- 기존 판단 변경 10건 및 과거 검증 우회 9건을 재현한다.
- 기존 10건이 발생하지 않은 최근 10편에서 판단 문장 40건을 별도로 선택해, 잠금 규칙을 모르는 생성자가 미묘한 판단 변경 40건을 만들게 한다.
- **의미를 보존하는 정상 수정 40건**도 대조군으로 둔다.
- **탐지율, 정상 수정에 대한 오탐률, 실제 운영 성과**를 따로 보고한다. 실패 후 같은 사례를 재사용해 성공한 것처럼 집계하지 않고 새 표본으로 재시험한다.

**운영 초기**
- US·KR 일간에 먼저 1주 적용한 뒤 뉴스·산업, 주간, 일본으로 확장 여부를 결정한다.
- 첫 주에는 수정된 문단의 가독성 개선 유효율, 불필요한 수정률, 의미 변경률, '유지'로 판정한 후보를 평가한다. **탐지되지 않은 문단 20개/주**도 표본 조사해 누락 문제를 확인한다.
- 토큰 사용량은 첫 3개 발행본과 변경 이전 3개 발행본을 비교한다. 증가가 글당 15%를 넘으면 후보 길이 기준을 40→35자로 좁히는 안을 검토한다.
- 잠금을 통과한 **판단 변경 1건이라도 발견되면 흐름 편집을 중단**하고 원인 조사·픽스처 보강을 한다. 기존 번역투 점검은 유지한다.
- **§12 구조 편집 재측정은 2026-11-07 예정**. 반복, 다리 문장, 상투적 상관 설명, 보도 재서술 등 구조적 현상을 따로 측정한다.

## 10. 후속 작업과 판단 기준

1. **Codex의 v2.2 설계 검토 결과 확인**, 치명적인 새 결함이 있을 때만 설계를 보완한다.
2. 제한 범위의 코드를 구현하고 보안·원복·SHA 일치·발행 예외 및 무변경 회귀 테스트를 실행한다.
3. 40+40 독립 시험에서 **판단 변경 탐지 누락 0건**을 목표로 하면서, 정상 수정을 과도하게 차단하지 않는지도 확인한다. 테스트 통과는 완전한 안전성을 뜻하지 않는다.
4. US·KR 일간 1주 시범 운영에서 **원문 대비 의미 보존**과 **실제 읽기 쉬워졌는지**를 함께 평가한다.
