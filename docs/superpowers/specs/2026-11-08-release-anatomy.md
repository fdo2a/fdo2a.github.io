## What changed

1. **Roles** (`collect_market_data.ECON` 6th element, `macro_metrics.compute`). `scored` rows move the axes; `anatomy` rows (the Philadelphia Fed index — a regional survey must not move the national regime) are on the table and get an anatomy block, never a score. `new_releases` = scored only, and it alone feeds the regime gate, the policy gate, the transmission gate and the fold's tier-1 test. `anatomy_releases` = the rest. `headline_releases` = both, each with `role`.
2. **Book state** (`absent|corrupt|empty|ok`, passed explicitly). The tier-2 cap (`MAX_SECONDARY_RELEASES`) applies only while the book is not `ok` — it existed to stop the first run (every indicator new) from chasing a dozen releases (0f5c60d2). In the 98 runs after 9/20 it cut a release on one day.
3. **Introduced rows** (Census 4). A row the `ok` book has never seen is kept out of the scores on that day (a composition change must not move an axis by itself), seeded into `last_seen`, and dissected — unscored — only if its FRED release date is later than the book's date. A row missing today keeps yesterday's `last_seen` reading, so a failed fetch no longer makes tomorrow read an unchanged print as new.
4. **Factory orders absorb the durable-goods revision**: when both rows are new with the same reference month, it is the full M3 report; durable goods are cited inside the factory-orders block, whose primary is fixed to factory orders. Different months: two releases. Residual risk: FRED loading the factory-orders row a day late makes the durable revision read as its own release for that day.
5. **Components need two sources** (`us/anatomy.py`):
   - FRED as of the release date D: `fred/release/dates?realtime_end=report_date&sort_order=desc` gives D; `observations?output_type=1&realtime_start=D−40&realtime_end=D` gives the vintage rows. The current observation needs a row **starting on D**; the previous one is the value valid on D. The headline's own observation must also start on D, or the whole release has no components. CSV transport = no components.
   - The agency text: `data/releases/index.json` row `ok`, `verified`, and the **headline value checked** (`checks.value` or `checks.primary_checked`). Each component has sentence patterns written against real releases (`fixtures/anatomy/`, 47 components across 12 releases, all matched on 2026-11-08). A pattern binds the name, the verb, the value and the period word in one sentence shape, so 「average monthly gain of 31,000」, 12-month figures and table rows never fit. The sign comes from the verb, an explicit ±, or the word 「deficit」. Two different values for one component = ambiguous = out. Nothing after `…[이하 생략]` counts.
   - The value printed is FRED's, rounded to the text's precision; if the two disagree the component is dropped (we do not know which is right). Residual risk: both share the same error.
   - 2026-11-08 FRED vs text measurements that shaped the registry: PPI goods/services ids on FRED are not the seasonally adjusted series the lede quotes (dropped; core `WPSFD49116` matches); 「health care」 is `CES6562000101`, not `USEHS` (health care *and social assistance*); permits `PERMIT` 1,398 vs the release's 1,400,000 (dropped); construction residential/nonresidential are the *private* series `PRRESCONS`/`PNRESCONS`. Retail sales, PCE and GDP have no prose components (tables or landing pages only) — they get `text`/`none`.
6. **Order of the Actions steps**: Collect (FRED side) → Fetch primary releases → Sanitize → `xcheck_components.py` (text side; resets every release first, and uses only this run's complete index) → `eval_macro_regime.py` (copies the result into `macro_eval.json`, plus `anatomy_gaps`). Previously the evaluation ran before the texts existed.
7. **Private text**: the Philadelphia Fed's pages say 「All rights reserved」, so its verified text goes only to `_workspace/releases/` for the cross-check and is never committed (`published: false`). Its status can never be `text` — the writer cannot read it. Every release's whole verified text is also written there (untrimmed, for the cross-check).
8. **Block boundary** (`us/release_blocks.py`): the block is its matched `<div data-release>`; the old slice to the next marker let the last block of an axis card swallow the next axis's table (10/27 new-home-sales: one sentence, 75 figures; 11/03 durable goods 70 → 10). Violations: not a div, duplicate key, nested markers, unclosed or div imbalance, outside a `div.card` of §9 (legacy separate 경제지표 section exempt). Of the 2026 posts only 09-16 would fail (block outside a card).
9. **What a block owes** (`us/anatomy_gate.py`), by `anatomy_status`: `complete` (≥2 usable components) → 2 components evidenced; `partial` (1) → that one + 3 figures; `text` (verified publishable text, no component) → 3 figures; `none` → the canonical figures (actual, previous when different). Evidence = one clause with exactly one component name and its current figure: forecast sentences, 「X에서」 origins, figures after 전월·지난달·직전·앞서, changes in %p/포인트/bp, a name after 전월 and a percent figure without % are not evidence; a figure equal to a headline figure needs a clause without the headline's name. The status never reaches the page.
10. **Length**: §9 over 4,600 characters is a warning (`weight.warnings`); the abbreviated-day 2,400 is still a block but measured without the anatomy blocks.
