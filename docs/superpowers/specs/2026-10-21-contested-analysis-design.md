## 요청

사용자(2026-10-21): 「기존의 뉴스 정리 방식은 그대로 진행하되, 세간의 주목을 받고 있는 내용이라던가 서로 상충되는 부분이 많은 주제만 저 방식대로 추가로 정리해서 레포트에 반영해 … 발행 보고서와 클라우드 루틴에 추가」, 이어 「KR과 주간 보고서도 추가해」.

**Mac 이 꺼져 있으면** 그날 섹션은 자리표시로 남다가, 3일 안에 켜지면 채워진다.

## 계약

- **근거 대조(F01·N01).** 주장·근거·기사 관측치마다 원문 구간(span)이 그 기사 본문에 글자 그대로 있어야 한다 — 코드가 본문을 버리기 전에 대조하고 span 은 커밋하지 않는다. 시장 관측치는 모델이 레지스트리 열쇠만 고르고 값·단위·기준일은 코드가 `market_data.json` 에서 채운다.
- **검증 호출(F01·F04).** 추출과 다른 호출이 쌍(양쪽 지지·양립 불가)·근거·관측치·분석 항목(근거 지지·조건부·권유 없음)을 판정한다. 실패 쌍 → 고아 주장·관측치 제거 → 분석이 지워진 근거를 참조하면 분석 전체 폐기(`analysis_unverified`, 재시도 가능). 재생성 루프 없음.
- **ok 조건(N02).** 생존 쌍 ≥1(쟁점·출처쌍·명제 기준 중복 제거), 최종 기사 독립 출처 ≥3, 분석 검증 통과, 스키마·문체 통과. 트리거 기록: attention(허용 매체 ≥5곳) / conflict(쟁점 ≥2개).
- **신빙성(F02·N03).** 높음 = 이 리포트의 시장 데이터로 검증 호출이 지지 판정. 중간 = 기사가 이름 붙은 통계·문서·관측을 전함(원자료 미확인). 낮음 = 일화·전언·근거 없음, 또는 익명 의혹. 같은 발표를 여러 매체가 전한 것은 교차 확인이 아니다. 루브릭은 캡션에 인쇄.
- **「사실상 가능성 낮음」.** 확률이 아니라 「필요 조건 + 지금 반대를 가리키는 관측치(counter_obs)」. 반대 관측치가 없으면 그 칸에 두지 않는다.
- **정규 렌더(F06·N07·N08).** 섹션 전체를 JSON 에서 찍고 모든 문자열을 이스케이프한다. 게이트는 같은 JSON 의 정규형(및 가독성·색 변형을 입힌 형)과 문자열 동일성을 요구한다. `template`·`hidden`·`display:none` 조상, 중복 속성, 잔여 표식, 복수 섹션을 막는다.
- **상한(N14).** 순위 1(sonnet, 제목만) + 추출 1 + 검증 1(opus) `claude -p` 호출, 본문 ≤6×20,000자, GDELT 최대 2회(20초 간격, 429 한 번 식힘), 수집 마감 900초(알람), 호출당 900초. 토큰은 `diagnostics.tokens`. 모델은 환경 변수 `CONTESTED_MODEL`·`CONTESTED_PICK_MODEL`. 전부 Mac 에 로그인된 구독 한도를 쓴다(5시간·주간 한도는 루틴과 공용).
- **공개 데이터(F15).** 본문·span·로그 본문 금지. 공개 필드는 메타데이터·한국어 의역·판정·코드형 사유뿐. 디버그 덤프(`CONTESTED_DEBUG`)는 레포 밖 로컬 폴더에만.

## 게이트가 증명하지 못하는 것

정규형 동일성은 「발행본이 검증된 데이터와 같다」까지다. 추출·검증 호출의 의미 판단(주장이 원문 뜻과 같은가, 두 주장이 정말 양립 불가인가, 인과 해석이 타당한가)은 모델 판정이며 증명이 아니다. span 대조는 원문에 그 구간이 있다는 것만 보이고, 의역이 충실하다는 것은 보이지 않는다.

**재시도.** 고른 후보에 일시 실패(`fail`·`robots_unavailable`·`time_cap`)가 남거나 발견·확장이 창을 다 못 봤으면 동결 none 대신 `fetch_incomplete`(US 도 같은 규칙). `blocked`(robots·허용 목록·403)는 영구라 세지 않는다. 검색 창을 다 못 본 날 후보가 없으면 동결하지 않는다.

**발행 뒤 채우기(KR).** `apply_readability` → `check_contested` → strict readability → style → `verify_post`(자기 대조, 레이아웃만) → 섹션 밖 본문이 바이트 그대로인가 → KR 데이터 게이트(session·weight·news·movers·fund)를 **그 글을 넣은 커밋의 kr/data** 로 앞판·뒷판에 돌려 새 실패만 막는다(원래 실패하던 게이트는 섹션 탓이 아니다). 못 넘으면 생략 기록.

**사후 검토.** 쟁점 자리만 바뀐 판(자리 정규화 뒤 앞판과 같음; 자리가 사라진 판은 그 커밋 결과가 확정 non-ok 일 때만)은 발행 커밋으로 치지 않는다 — 근거는 원래 발행 커밋의 kr/data. 판은 검토 대상으로 남고(조판으로 넘기지 않는다), 검토자에게는 섹션을 뺀 글을 준다. 정정 재생 게이트에 그 판의 JSON 으로 `check_contested`, 정정 진입 검사도 쟁점 자리만 다른 판을 받는다. 문체 패스는 쟁점 섹션 문단을 뽑지 않는다(`prose_swap`).

**남은 위험.** 약관(위). 순위가 코드라 「엇갈릴 만한 사건」을 모델보다 못 고를 수 있다(시황 감점·논쟁 가점으로 보정, 10/20 실측 1순위 = 원·달러 연저점). 출력 토큰 상한은 CLI 에 없다. US 는 기준 시각 고정·일시 실패 동결 금지 가운데 앞의 것을 아직 쓰지 않는다(후속).
