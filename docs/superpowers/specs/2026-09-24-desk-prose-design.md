## 원인 — 작성자가 아니라 계약과 도구

1. **단조 검사가 수사의문을 보상했다.** `style.MAX_SAME_ENDING_RUN` 은 「~다」 종결 4연속을 막았다. `-다` 로 쓰는 작성자가 연속을 끊을 수단은 질문·`-습니다`·「~죠」뿐이다. KR 9/23 §2 event 는 「…올랐다. 나머지 업종은 어땠을까? …내렸다.」로 정확히 네 번째 자리에 질문을 넣었다. US 가 회차마다 어미를 바꾸고 9/21 에 「~죠」가 나온 것도 같은 압력이다. [[조판기 vs 작성 계약]] 과 같은 모양 — 글이 이상하면 도구부터.
2. **계약이 서로 달랐다.** US writer 상단·DESK_REPORT 는 PM, 같은 파일 「말하듯이 쓴다」는 「독자는 개인이다」, KR writer 는 「US 는 개인」. US 는 어미를 정하지 않았다(「-다 나 -습니다 하나를 기본으로」).
3. **뉴스 요약 프롬프트가 `-습니다` 를 강제했다** — -다 본문에 뉴스만 다른 목소리.
4. **판정 신호가 작업 어휘를 받아 줬다.** `stance_gate.VERDICT_CUES["판정불가"]` 에 「원장」·「부트스트랩」이 있어, 원장 이야기를 쓰면 게이트가 통과시켰다.
5. **가격이 데이터에 없었다.** 개별주 등락률이 KR 수집에 없어 작성자가 「파이낸셜뉴스는 삼성전자가 3.25% 올랐다고 전했다」로 신문을 가격의 출처로 삼았다(수치는 데이터에서만 규칙을 지킨 결과).
6. **예문이 질문형이었다.** KR writer 의 「…설명할 수 있는가? … 무엇인가?」.
7. **금지 규칙이 본문 문장이 됐다.** 「외국인 주식 수급은 채권 자금의 증거가 아니다」가 「…증거로 연결하지는 않는다」 문단으로.

## 설계

- **선언**: `<body data-register="da">`. 일간은 `post_shell.render` 가, 주간·월간은 작성자가 달고 `period_gate` 가 확인한다. 선언 없는 문서(중국 학습·과거 발행본)는 새 검사를 받지 않는다 — 교정 러너가 옛 발행본에 `check_style` 을 다시 돌려도 멀쩡한 글을 막지 않는다. `<body>` 태그에서만 읽는다(본문에 그 문자열이 나와도 판정이 뒤집히지 않게).
- **실패**: 산문 `<p>` 의 -습니다·-죠·-요 종결 3개 이상 / 물음표 문장 2개 이상 / 작업 어휘(캡션 포함, 근거 블록·생성 구간 제외) / 「국채 급등·급락」(제목 포함) / 근거 블록 3개 이상 또는 600자 초과 / 같은 두 글자 종결 4연속.
- **경고(exit 0)**: 줄표 7개 이상 / 단서 문장 7개 이상 / 같은 수치 4회 이상.
- **제외 구간**: `<section data-research-summary>`(원장에서 생성·바이트 대조 — 렌더러를 바꾸면 과거 주간이 깨진다), `<details data-provenance>`(재현 계산 자리).
- **작업 어휘의 오탐 방지**: 앞 글자가 한글이면 다른 낱말(금감원장), 밴드는 크기 라벨 바로 뒤만(볼린저밴드 제외), 분위는 숫자 뒤·「기」 앞이 아닐 때만(분위기 제외).
- **풀이 의무**: 데스크 문서에서는 GLOSS 첫 등장 풀이를 검사하지 않는다(PM 에게 교과서). PLAIN 음차는 그대로 막는다.
- **KR 데이터**: `kr_stock_moves.json` — 코스피 거래대금 상위 60 개별주의 등락률. 같은 marketValue 응답에 이미 있던 `fluctuationsRatio` 를 버리지 않고 쓴다.

## 하지 않은 것

- **매크로 축 점수를 표로 빼기** — `macro_gate` 가 산문 속 점수를 대조하고 이미 `span.sub` 작은 글씨다.
- **윤문(STEP 2.5)을 점검표로 교체** — 9/24 토큰 정리에서 사용자가 윤문을 건드리지 말라고 했다. 점검표(`STYLE_EXEMPLARS.md` §5)만 앞에 뒀다.
- **연구 판단 복기 렌더러의 `-습니다`** — 불변 생성 구간이라 검사에서 뺐다.
